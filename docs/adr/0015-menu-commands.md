# ADR-15: Honest menus — ghosting, spare page, cycling, palette files, fixed background

- Status: accepted (Phase 3, 2026-11-10)
- Context: The menus showed the whole DeluxePaint IV AGA menu set, but most items did nothing. The owner asked for visible results fast: implement the menu commands that are cheap now and make the rest visibly unavailable, with a mechanism later features extend. References: manual AGA p.69, p.232–235, p.241–243, p.256, p.266 (via `docs/research/manual-ui-notes.md` §2).
- Decision:
  - **Ghosting (`dpx_ui::menu`).** `menu::IMPLEMENTED` lists the command ids that work; every other command item is drawn ghosted and cannot be chosen. A submenu item whose items are all ghosted is ghosted and does not open (Intuition behaviour); a menu whose items are all ghosted has a ghosted title but still drops down (Brush and Anim for now). Mode, Prefs and Pixel Size items stay enabled (HBrite still needs an EHB screen). New features add their id to the list; `palette.mixer` is listed for the Color Mixer built in parallel.
  - **Picture ▸ Spare** (`j` Swap, Ctrl+`j` Copy to Spare, Merge in Front, Merge in Back, Delete This Page). The app keeps the other page as a second command engine. Both pages share palette and screen format; each keeps its own undo history, scroll position, file name, fixed background and BG colour (AGA p.69: "BG colours may differ"). The spare starts as a blank page (colour 0) of the shown page's size.
    - Swap exchanges the two engines; it is not an undo step (DeluxePaint cannot undo it either), but nothing is lost: each page undoes its own steps.
    - A spare of another screen format is dropped when it is next used, as DeluxePaint discards the spare on a format change (AGA p.241). If only the palette changed meanwhile, the spare takes the current palette and its undo history starts over.
    - Merge in Front / Back are one undoable `MergePage` command each (new in `dpx-core`). **Deviation:** colour 0 is the transparent colour; the manual says the page's BG colour. With the default BG (colour 0) both agree; `MergePage.transparent` lets a later wave pass the BG colour.
    - Copy to Spare is one `SetPage` step on the spare page (the whole page, not only the visible part as the manual says for pages bigger than the screen).
    - **Deviation:** Delete This Page does not ask first. It is one undoable `SetPage` step that replaces the shown page with the spare (or a blank page) and frees the spare; Undo brings the deleted page back.
  - **Picture ▸ Delete..** opens the file requester titled "Delete File" with a Delete button. Delete (button, Return or a double-click) shows the Yes/No box "Delete this file?"; only Yes (or `y`) removes the file, then the requester closes. Any file type can be deleted, as in DeluxePaint.
  - **Picture ▸ About..** shows our own short text (name, version, licence, "not affiliated with Electronic Arts", page size, colours and mode) in the note requester; `?` opens it too. No original credits. Memory figures make no sense here and are left out.
  - **Picture ▸ Print..** is ghosted (no printing planned yet).
  - **Color ▸ Cycle (Tab)** rotates the CRNG ranges loaded with the picture (`PictureExtras.ranges`) at their rates (16384 = 60 steps per second). Only the shown palette rotates: pixels and the document palette stay unchanged, so Save writes the uncycled palette. Forward ranges move each colour one entry up (the highest wraps to the lowest); reverse ranges (flag bit 1) move down; inactive ranges (flag bit 0 clear) and rate 0 never move. While cycling, the app repaints about 60 times a second. The UI pens follow the shown palette like everything else on the screen. A new picture has no ranges until the Range requester exists; DeluxePaint's default ranges are not provided yet.
  - **Palette ▸ Restore Palette** goes back to the palette of the last loaded picture (the start palette before any load); undoable. **Deviation:** the manual's "previous palette" is the palette before the last palette change; ours is the loaded one, as decided for this wave.
  - **Palette ▸ Load.. / Save..** use the file requester. A palette file is an ILBM with BMHD (screen size, plane count for the palette size, aspect) and CMAP plus the CRNG ranges that fit, and no BODY — the layout DeluxePaint uses. Load reads the CMAP of any ILBM (also full pictures; 4-bit CMAPs are scaled like the picture loader does) and replaces the palette from colour 0 on as one undoable step; a file with more colours than the picture loads the first ones, one with fewer leaves the rest unchanged, and a note says so. Its CRNG ranges replace the current ones. Save asks before replacing a file.
  - **Palette ▸ Use Brush Palette, Arrange, Color Set** are ghosted (no brushes / Arrange requester / colour sets yet).
  - **Effect ▸ Background ▸ Fix** remembers the shown page; CLR (toolbox and `k`) then puts that picture back (one undoable `SetPage`) instead of filling with the BG colour. **Free** forgets it. If the page size changed since Fix, CLR fills with BG again.
    - Not done: painting with the right button does not erase back to the fixed background yet (tool code), and the "B" flag in the title bar is missing (the title bar is drawn in `screen.rs`, outside this change). **Lock FG** is ghosted until stencils exist.
  - **Effect ▸ Stencil, LightTable, AntiAlias, Process, Translucency, Perspective**, the **Anim** and **Brush** menus, Color ▸ Ranges, Remap, Recompute and Color ▸ Brush are ghosted for later waves.
  - New commands in `dpx-core`: `SetPage { width, height, pixels }` (whole-page replacement; another size must fit the page limits) and `MergePage { width, height, pixels, front, transparent }` (top-left aligned, clipped). Both validate size and colours and are undoable like every command.
- Verified:
  - `dpx-core` tests: MergePage in front/back with clipping, refused colours and sizes; SetPage same size and new size, JSON shape.
  - `dpx-ui` tests: every id in `IMPLEMENTED` exists in the menus; unimplemented commands, empty submenus and whole menus are ghosted, Mode/Prefs/Pixel Size are not; a ghosted submenu does not open; the Delete File requester asks before answering.
  - App tests (`menu_actions.rs`): swap keeps both pages, their undo and BG colours; merge front/back with colour 0 transparent and undo; Copy to Spare (Ctrl+`j`); Delete This Page and undo; a spare of another format is dropped; Fix + CLR (toolbox and `k`) + undo + Free; palette Save → Load round trip through the file requester (BMHD, CMAP, CRNG, no BODY) with undo, CMAP from a full picture, refused non-ILBM; Restore after a load; Delete only after Yes in a temp drawer; cycling rotates the shown palette over time (forward, reverse, rates, inactive ranges) while document palette and pixels stay unchanged; About via menu and `?`.
  - Headless snapshot `docs/design/screenshots/phase3-menus.png` (`--menu 4:2`: Color menu with the Palette submenu; Brush and Anim titles ghosted), looked at.
  - Not tried by hand in the window: the Tab/`j`/`k` keys, cycling speed on screen, and the requesters were only driven by tests.
- Consequences:
  - Later waves enable a menu item by implementing it and adding its id to `menu::IMPLEMENTED`.
  - `PainterApp::palette()` is now the *shown* palette (cycled while Color ▸ Cycle is on). Code that changes the palette must start from `engine.document().palette()`.
  - The spare page is app state, not part of the document; the `.dpxproj` format (later) decides whether it is saved.
