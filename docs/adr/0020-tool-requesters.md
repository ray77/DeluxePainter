# ADR-20: Toolbox settings requesters and Stencil

- Status: accepted (Phase 3, wave 2)
- Context: Grid, Symmetry, Airbrush and the Fill tool worked with fixed values (16-pixel grid, 6-fold cyclic symmetry, radius 10, solid fill; ADR-14). DeluxePaint IV opens the Gridding, Symmetry, Spacing and Fill Type requesters with the right mouse button on the toolbox buttons (`docs/research/manual-ui-notes.md` §1.5, §3.6–3.10) and has Effect ▸ Stencil to protect colours.
- Decision:
  - **One modal requester slot**: `UiState::tool_requester: Option<ToolRequester>` (`dpx-ui`), an enum over Grid, Symmetry, Spacing, Fill and Stencil. Gridding, Symmetry, Spacing and Fill Type are built from a small shared `Form` (radio buttons in groups, check boxes, numeric fields, Cancel/Ok; Return = Ok, Esc = Cancel, Tab next field, Up/Down change a number, out-of-range numbers keep the requester open with a message). Our own pixel widgets with the palette pens; disabled options use `pens.ghost`, a checker only if there is none. `apps/deluxepainter/src/settings.rs` opens them, feeds events and stores the result in `ToolState`.
  - **Opening**: right-click on Grid, Symmetry, Fill, and on the Dotted/Continuous Freehand, Line, Curve, Airbrush, Rectangle, Circle, Ellipse and Polygon buttons (either half); keys `F` (Fill Type) and `V` (Spacing). Right-click selects the tool like a left click, except Grid and Symmetry, which are not toggled.
  - **Gridding**: X and Y spacing, 1–512 pixels (`ToolState::grid_size`, default 16×16). The snapping tools are as before (ADR-14).
  - **Symmetry**: Cyclic or Mirror and the order 2–40 (`ToolState::symmetry_settings`). `dpx_core::Symmetry` got `mirror: bool` (serde default false, omitted when false, so old JSON is unchanged) and `count()`: Mirror gives `order` rounded down to an even number (at least 2) of copies, half rotated and half their left/right mirror images; order 2 is a plain mirror, order 4 mirrors both ways.
  - **Spacing**: Continuous (default), N Total, Every Nth dot, Airbrush, plus the airbrush spray radius (1–99; also used by the Airbrush tool). It applies to Dotted/Continuous Freehand, Line, Curve and unfilled Rectangle, Circle, Ellipse and Polygon: the outline's pixel path is turned into brush stamps (`Shape::Dots`) in `tools.rs`: exactly N evenly spread stamps (both ends included), a stamp every N pixels, or N sprays per path pixel inside the airbrush radius. The sprays come from a hash of the pixel index, so a gesture redrawn from its points looks the same and the preview is the committed result. Still one command per gesture. Filled shapes and the filled freehand stay solid.
  - **Fill Type**: Solid, or a gradient: Vertical (colour changes top to bottom over the region's bounding box), Horizontal (left to right), Vertical Line and Horizontal Line (the same over the whole page, so different shapes match), optional ordered 4×4 dither between neighbouring colours. `dpx_core::gradient` (new): `FillType`, `Direction`, `gradient_color`, `flood_fill`, `range_for`. `Command::FloodFill` got `fill: FillType` (serde default `solid`, omitted when solid); a gradient carries its explicit `from`/`to` palette indices (validated against the palette; `from > to` runs the range backwards). The app picks the colour range (CRNG) that holds FG, else FG to BG (`ToolState::fill`, `PainterApp::fill_type`). The engine applies it as before, so undo, preview and MCP work unchanged.
  - Brush, Perspective, Contour, Ridge and Highlight are shown ghosted.
  - **Stencil**: Effect ▸ Stencil ▸ Make.. (`stencil.make`, `~` in the menu) opens a palette grid; a click toggles a colour as protected, a drag paints the state of the first swatch, Make/Clear/Invert/Cancel. Make with no colour protected means no stencil. The result is `PainterApp::stencil` (256 flags). `stencil.toggle` (On/Off) moves it aside into `ToolState::stencil_off` and back; `stencil.reverse` inverts the palette's colours; `stencil.remake` brings back the last made stencil (it is colour based, so newly painted pixels of a locked colour are protected already); `stencil.free` forgets both. All five ids are in `menu::IMPLEMENTED`; Show, Paint, Load and Save stay ghosted.
- Deviations from DeluxePaint IV:
  - Spacing also opens from the freehand buttons and Airbrush (DeluxePaint: Airbrush right-click is the size drag; there the radius is set in the requester instead). Spacing applies to the freehand tools as well, which the manual does not say.
  - Fill Type: no Brush, Wrap, Perspective, Pattern, Shape/Circle/Contour/Highlight gradients, no Random range, no direction-line click and no Color Fill box in the title bar. The four gradient directions are our own mapping (DeluxePaint's Line/Shap/Cir/Con/Hi types need the direction-line gesture); "Line" here means page-wide.
  - Gridding has no Adjust (drag a matrix on the page), no offset. Symmetry has no Tile and no Place (centre stays the screen centre). Mirror is our own N-copy kaleidoscope reading of "Mirror, order N".
  - Make Stencil: click toggles instead of left = select, right = deselect (requesters get left-button events only); no pick from picture, HAM tolerance or Show. Stencil flag `S` is not yet shown in the title bar.
  - Requesters are not draggable (ADR-13).
- Verified (unit and app tests, headless snapshot; not run in the interactive window):
  - gradient math (bands, descending ranges, dither only mixes neighbours, region vs page extent, solid fill unchanged, range choice, JSON, engine command with validation and undo); mirror symmetry copies; form widgets; each requester's input handling and limits; right-click opening, Ok/Cancel storing or dropping settings; grid snapping with changed spacing; mirror symmetry stroke; Every-Nth, N-Total and airbrush spacing results (including live freehand preview equal to the commit); airbrush radius; gradient Fill tool through the range rules and one undo step; stencil make/toggle/reverse/remake/free.
  - Snapshots: `--fill-requester`, `--grid-requester`, `--symmetry-requester`, `--spacing-requester`, `--stencil-requester [--protect 1,2,3]` (`docs/design/screenshots/phase3-requesters.png`).
  - Not verified: the real window (mouse and keyboard through egui, right-click on the toolbox); behaviour of the original program for any of the above.
- Consequences:
  - `FloodFill` does not go through `paint::plot`, so the stencil does not protect flood-filled pixels yet; whoever wires `app.stencil` into the paint commands must add it there too (or leave the Fill tool unstencilled, as DeluxePaint's flood fill is a region operation).
  - Settings are not saved with the project.
