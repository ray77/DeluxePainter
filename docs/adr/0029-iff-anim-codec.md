# ADR-29: IFF ANIM codec (library only)

- Status: accepted (Wave 4, `dpx_iff::anim`; not wired into the app, the integrator connects it once project frames exist)
- Context: DeluxePaint IV animations are IFF ANIM files. Sources: `docs/IFF_SUPPORT_MATRIX.md` §5 (from [S15], the ANIM wiki page); no real ANIM file was available (`Examplepics/` holds six ILBM pictures only) and no source describes what DPaint IV itself writes.
- Decisions:
  - Module `crates/dpx-iff/src/anim.rs`: `read`, `read_with_notes` -> `Anim` (all file frames as full `IndexedImage`s, first palette, CRNG/CAMG/aspect of the first picture, DPAN, `loop_frames`), `encode(frames, palette, &EncodeOptions)`, `encode_op5`, `apply_op5`, `Anhd`, `Dpan`. Errors are `AnimError` with `kind`, a first line of at most 34 characters and details (ADR-17 style); notes list what is tolerated.
  - Layout read and written: `FORM ANIM { FORM ILBM {BMHD CMAP [CRNG] [CAMG] ANHD DPAN BODY}, FORM ILBM {ANHD DLTA [CMAP]} ... }`. DPAN is also accepted directly inside the ANIM.
  - Double buffering: a delta applies to the frame `interleave` frames back (0 means 2). The first delta frames have no such frame; both buffers start as copies of frame 0, so a reference before frame 0 means frame 0 (frame 1 is a delta against frame 0, frame i >= 2 against frame i-2). Interleave 1 (anim brushes) is supported by the same rule.
  - Method 5 (Byte Vertical Delta): 16 LONG offsets (8 used, 0 = plane unchanged), per plane and per byte column an op count byte, then Skip (1..127 rows), Uniq (0x80 | n literal bytes) and Same (0, count, value). Byte columns are word-padded rows (a 17 pixel wide picture has 4 columns). Reader errors name frame, plane, column and what was exceeded. The reader accepts XOR mode when ANHD `bits & 6 != 0`: the sources disagree (spec table bit 1 = value 2, DPaint anim-brush description value 4), and method 5 has no other option bit. The XOR area fields (x, y, w, h) and the plane mask are read but ignored; the delta is applied to the whole picture.
  - Writer: method 5, set mode, interleave 0, bits 0. Unchanged gaps of at most 2 rows are written as literals (a skip plus a new literal header costs as much); if a column needs more than 255 ops (one op count byte), gaps are merged more and more, finally all-literal. Pictures taller than 32385 rows (255 ops of 127 rows) are refused. Plane data start on even offsets. Closing loop frames: for N >= 2 frames two more deltas are written, frame N = frame 0 (against frame N-2) and frame N+1 = frame 1 (against frame N-1); with the double-buffer rule a player that restarts at the third frame loops seamlessly. This is the DPaint convention described in the matrix; the exact bytes DPaint writes were not seen. One frame is written as a plain picture, no closing frames.
  - Timing: ANHD `rel_time` is in jiffies (1/60 s) since the previous frame. `Anim::hold_jiffies(i)` = `rel_time` of the next file frame (for the last logical frame the first closing frame). The first frame has `rel_time` 0 (its hold time when it is the only frame). DPAN has no rate field (version, nframes, flags); the rate is only in ANHD.
  - Loop detection when reading: `loop_frames` is 2 when DPAN nframes + 2 equals the frame count, or when nframes equals the frame count (or DPAN is missing or disagrees, with a note) and the last two frames equal the first two. Which count DPAN holds in real DPaint files is not known; our writer stores N without the closing frames. Corner case: a file written with `loop_frames: false` whose last two frames happen to equal its first two is read with `loop_frames` 2 (no data is lost, only the view `logical_frames()`).
  - Per-frame CMAP: stored as `AnimFrame::palette` (the previous palette with its first entries replaced); `Anim::palette_at(i)` gives the palette in effect. Not written.
  - Methods 7 and 8 are refused (`ANIM method 7: not supported`, details name the method and which ones are read). They need exact layouts and the only source is the summary in the matrix; nothing could be checked against a file. Methods 1-4, 6 and J are refused too. A first frame without BODY (delta against black) is refused.
  - Limits: 1 << 30 pixels over all frames when reading; a cut-off file keeps the frames before the cut (note); at most 65533 frames written (DPAN has 16 bits).
- Deviations from DeluxePaint IV: only op 5 is written (what DPaint IV writes is unverified); interleave is written as 0; CRNG only on the first picture; no per-frame palettes written; first-frame mask planes are dropped with a note.
- Verified (tests in `crates/dpx-iff/tests/anim.rs` and the module, run twice, green): byte-level golden op-5 chunks checked by hand (Skip+Uniq, Same, plane offsets), round trips encode -> decode for sizes 1x1 to 320x40 (odd widths), 2/32/256 colours and 1/2/3/4/7/10 frames, with and without closing frames, identical frames, full-change frames, 16x700 checkerboards (column op overflow path), per-frame hold times; a hand-built file (independent of the writer) for double buffering, interleave 1, XOR with both bit values, method 0 frames, per-frame CMAP, cut-off file; exact refusal texts and kinds, first lines at most 34 characters.
- Not verified: any real ANIM file (none available; `Examplepics/` has no ANIM, the test that scans it prints what it finds when one is present); DeluxePaint IV or Amiga players reading our files; the closing-frame convention and DPAN frame count against DPaint output; the `rel_time` hold interpretation; XOR semantics against a real anim brush.
