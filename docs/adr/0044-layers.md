# ADR-44: Layers: the layer model, its commands, project format version 3 and the layer panel

- Status: accepted (2026-11-12, wave 8; the owner decided that layers are built now and approved the panel's mockup, see Owner decisions; the points under "Decided without the owner" were not asked). Part 1 (model, commands, format, readers) and part 2 (the layer panel, its key and menu item, the title-bar name) were built one after the other on the same branch; part 3 fixes the review findings on both (its decisions are marked "part 3" below; its tests are listed under Verified).
- Context:
  - Since ADR-28 a document is 1..N animation frames of one size, one palette and one target, each frame one indexed page; the current frame is "the page" every page command paints. `docs/ARCHITECTURE.md` planned a layer tree; nothing was built. The owner's MCP and image-generation specification asks for layers (`list_layers`, `create_layer`, `select_layer`, generated pictures as a new layer) and the owner decided to build them now.
  - DeluxePaint IV AGA has no layers (its Spare page and stencils are the nearest things). This is a DeluxePainter addition; it follows the frame model of ADR-28 wherever there is a choice.
- Owner decisions (wave 8, binding):
  - Layers are built now. A layer panel at the right edge, toggled by a key and a menu item (part 2), as in the owner's mockup: the title "Layers", one row per layer from the top layer down with an eye box, the name and a marker on the active layer; buttons New, Copy, Del, Up, Dn, Merge; rename by double-clicking the name. In layout C it sits in the work area right of the picture when there is room, otherwise over the screen's right edge.
  - On every layer above the bottom one palette colour 0 is transparent: painting with colour 0 erases there.
  - Layers are only visible or hidden (no % opacity). No layer groups yet.
  - A generated picture's target is Spare page / Picture / Brush; "New layer" comes with the integration step.
- Decision:
  - **Model (`dpx_core::Document`, `dpx_core::layer`):** one layer stack per document, shared by every frame: `Layer { name, visible }`, bottom first; layer 0 is the bottom layer ("Background" in every new document). Every frame holds one indexed picture per layer, all of the page size, all in the document palette and target. The document has an active layer. `Document::page()` is the active layer of the current frame, so every page command (strokes, shapes, fills, CLR, Flip, BG->FG, BG<->FG, SetPage, MergePage, Stenciled, AnimBrushPaint) paints it unchanged; `frame(i)`/`frames()` are the active layer of each frame (the AnimBrush pick-up and Anim ▸ Move paint and read them). New accessors: `layers()`, `layer_count()`, `active_layer()`, `layer(l)` (current frame), `cel(f, l)`, `cels()` (every picture), `from_layers(..)`.
  - **Storage:** the page plus every other picture behind an `Arc`, frame by frame and bottom layer first (`others`); a single-layer document keeps exactly the list it had before (its other frames), so its undo snapshots and byte counts are unchanged. Selecting a layer or a frame moves the page in and out of that list (`Document::focus`). A new layer is one clear picture shared by every frame, a duplicate shares the copied pictures; a picture is copied when it is painted.
  - **Transparency and the composite:** above the bottom layer colour 0 is transparent; the bottom layer is opaque. `Document::composite()` / `composite_frame(i)` / `composite_frames()` give a frame as it looks: its visible layers bottom to top (`layer::flatten`); the lowest visible layer is copied as it is (over a hidden bottom layer an upper layer's colour 0 shows colour 0, the colour of an empty page), nothing visible gives colour 0. With one visible layer (every single-layer document) the composite is that layer itself, borrowed (`Cow::Borrowed`), so single-layer documents show and export bit-identical to before without a copy. `composite_with(img)` / `composite_frame_with(i, img)` put a stroke preview in the active layer's place.
  - **Commands (JSON `op`, layer numbers from 0 = bottom):** `add_layer {name?}` (a transparent layer above the active one, which becomes active; default name "Layer N", the smallest N unused), `duplicate_layer {layer}` (above it, name + " copy", same visibility; the copy becomes active), `delete_layer {layer}` (never the last; the layer below becomes active when the active one goes, the new bottom layer when the bottom one goes), `move_layer {from, to}` (the others close up; the active layer stays the same layer), `select_layer {layer}`, `set_layer_visible {layer, visible}`, `rename_layer {layer, name}` (at most 255 characters, the project format's limit), `merge_layer_down {layer}` (layer >= 1: its pixels other than colour 0 cover the layer below in every frame, shown or hidden; the result keeps the lower layer's name and visibility), `flatten_layers` (every frame becomes one layer showing what it shows, hidden layers go; it keeps the bottom layer's name and is visible), `set_picture {width, height, layers, frames, current?, active?}` (part 3: the whole picture, every frame with every layer and the stack, replaced in one step; `frames[f][l]` holds the pixels of layer `l` of frame `f`; palette, target and rate stay; another size must be a page the target allows, and the layer and frame limits hold; `Command::set_picture(&doc)` makes one from a document). At most 32 layers (`layer::MAX_LAYERS`).
  - **History:** every layer command is one undo step, except `select_layer`, a setting like `goto_frame` (no undo step, the revision counts, the redo list stays). Undo steps remember the active layer as they remember the frame (ADR-28): undoing or redoing a pixel step of another layer selects that layer first, and the outcome names the whole page. Footprints: add, duplicate, delete, move, merge and flatten snapshot the document (`Footprint::Layers`; the pictures are shared, only what the step keeps alive counts for the byte budget); visibility and rename keep only the names and flags (`Footprint::LayerInfo`). The outcome of every layer command names the whole page (what it shows may change); palette and format are unchanged.
  - **Commands that touch every picture:** Screen Format without Retain clears the page to one "Background" layer (all frames, the active layer 0); with Retain every layer of every frame takes the new size and the colours of every layer count for the palette size. Page Size gives the new area the BG colour on the bottom layer and colour 0 (transparent) above it. Frame commands (Set #, Add, Copy, Insert copies, Delete) copy, move and delete a frame with all its layers; deleting every frame leaves one frame with the bottom layer in BG and the upper layers clear. Arrange Palette renumbers every layer of every frame and keeps colour 0 at 0 above the bottom layer (`remap::arranged_picture`); an order that would make another colour entry 0 is refused (`PALETTE_RANGE_INVALID`) when an upper layer uses that colour, since it would turn transparent there. Merge in Back (`merge_page` with `front: false`, part 3) puts the other page only where the frame as it shows (all visible layers) and the active layer are both the transparent colour, so it lies behind the whole picture; with one visible layer that is the page, as before. Color ▸ Remap is now the command `remap_colors {from}`: every layer of every frame is repainted (nearest colour), and above the bottom layer colour 0 stays 0 and no other colour becomes 0. SetPage of another size is refused with more than one layer (as with more than one frame).
  - **Limits:** frames times layers times page pixels must stay within ADR-28's 128 MiB (`anim::max_frames_for_layers`; the frame requesters' maxima follow it). With one layer at least one frame is always allowed, as before; with more, a frame of that many layers must fit. The project reader's entry limit becomes 999 frames x 32 layers + 2 = 31 970 so every document the program allows can be read back.
  - **Project format version 3** (`docs/PROJECT_FORMAT.md`): written when the stack is not the one visible "Background" layer (more than one layer, or one renamed or hidden layer): the version-2 fields plus `layers` (name, visible, bottom first) and `active_layer`, and `frames/<n>/layers/<k>.png` per layer, the frame entries listing their layers' pictures in stack order. Part 3: version-3 frame entries carry no `name` (the stack names each layer once; a name the reader finds there must be the stack's), so names of 255 characters no longer repeat for every frame and the manifest of the largest document the program allows stays far below the reader's 1 MiB; versions 1 and 2 still name every frame's layer. Everything else is written exactly as before (version 1, or 2 for animations), byte for byte, so single-layer projects still open in older builds; older builds refuse a layered project as "from a newer version" instead of dropping layers. The reader takes versions 1, 2 and 3; a version-1/2 file's layer keeps the name its frames give it (DeluxePainter always wrote "Background").
  - **Exports and the CLI:** ILBM, PNG and ANIM hold what the frames show, the composite (`files::encode_document`, MCP `pictures::encode_document`; there is no HAM or EHB writer yet: an EHB picture saves as a 64-colour ILBM through the same path, ADR-26). With more than one layer, or a hidden one, the save notes it ("3 layers saved as one picture, as shown, 1 hidden layer left out (save as .dpxproj to keep them)"). `.dpxproj` keeps every layer and notes nothing. `info` lists the layers of a project that has more than the default one and counts the colours of every layer; `convert` goes through the document and so flattens like Save.
  - **Autosave and recovery** (ADR-34) write and read the same project format, so they keep every layer, the active layer and the current frame.
  - **MCP (headless):** `get_pixels` and `render_png` read the composite of the current frame; `save_picture` exports the composite with the note; the hardware check looks at every layer. `execute_command` accepts the layer commands as it accepts every `Command`. No layer tools and no layer fields in `get_document_state` yet (integration step).
- Decision, part 2: the layer panel (`dpx_ui::layer_panel`, `apps/deluxepainter/src/layers.rs`):
  - **Look:** an 80-pixel-wide column (UI/LoRes pixels, square corners, 1-pixel bevels, palette pens, the bitmap font). An 11-row title row drawn like the screen's title bar ("Layers"); one 10-row line per layer from the top layer down: a marker (a small triangle) and a lit name (the `select` pen, text in `shine`) on the active layer, an eye box (a dark frame with an eye while the layer shows, empty while it is hidden), the name cut at the column's edge (as the mockup cuts "Sket", "Back"); at the bottom three rows of buttons: New | Copy, Del | Up | Dn, Merge (the whole width). A button whose command the engine would refuse is ghosted (a dry run of that command each redraw: Del with one layer, Up on the top layer, Dn and Merge on the bottom layer, New and Copy at 32 layers or the memory limit) and a click on it does nothing. A dark 1-pixel line is its left edge.
  - **What the clicks do** (left button; the right button does nothing on the panel): a row's eye box runs `set_layer_visible` (toggles); the rest of a row runs `select_layer`; a second click on the same row within 500 ms (the file requester's double-click time) opens a string gadget on the name (dpx-ui's `TextField`, printable ASCII only, at most 255 characters): Return runs `rename_layer`, Esc keeps the old name, and a click anywhere else takes the name as Return does and does nothing else (it never paints). An empty or unchanged name runs nothing; "unchanged" is the text the gadget opened with, so a name with characters the gadget cannot show (from MCP or a project) keeps them unless something is typed (part 3). While the gadget is open it takes every key (no tool, menu or undo key acts). New runs `add_layer` (above the active layer, "Layer N"), Copy `duplicate_layer` of the active layer, Del `delete_layer`, Up / Dn `move_layer` one step, Merge `merge_layer_down`, each on the active layer. Every one of them is one undo step (selecting is a setting, ADR-28/ADR-44 part 1), so `U` / Shift-`U` and the toolbox's Undo take them back. Flatten has no button (it is not in the mockup); it stays a command (`flatten_layers`, `--commands`, MCP `execute_command`).
  - **Many layers:** when the rows do not fit (19 rows on a PAL LoRes screen under the title bar, 12 on an NTSC screen above the Control Panel; up to 32 layers), two arrows in the title row scroll the list one row per click and the wheel over the panel scrolls it (the page does not scroll then); the list scrolls by itself so the active layer shows whenever it changes.
  - **Where it sits (layout C):** the window snaps to the picture's screen (ADR-13), so the only work area beside the picture is the dark area around the centred screen of a full-screen or maximized window. There, when screen and panel fit side by side at the screen's pixel size, the panel is **docked** right of the screen (right of the toolbox), as high as the screen, its title row in line with the title bar; screen and panel are centred together. It is a second texture painted right of the screen texture at the same pixel size, so the screen itself (and every snapshot and test of it) is unchanged. Everywhere else (a snapped window, or no room) the panel lies **over the screen's right edge**, left of the toolbox (at the right edge while F10 hides the toolbox), below the title bar (from the top while F9 hides it) and above the Animation Control Panel when that is shown; it is drawn under the menus and requesters like the toolbox. Layout A ("Classic screen", design checkpoint 1) is not built; it would use the overlay. When the panel docks or undocks in a pass that already laid the screen out (Prefs ▸ Layers, `L`, entering full screen), nothing is painted beside the screen in that pass and another pass is asked for at once.
  - **Stencil ▸ Paint** (part 3): a press on the panel that can change the document (a button that works, an eye box, a row) ends Stencil ▸ Paint first, as a menu item does, so its command reaches the picture and `U` undoes it rather than a stroke of the mask; the scroll arrows and ghosted buttons leave it on.
  - **Requesters:** while a requester, note, Show Page, playback, Set Range or Move (`modal_open`) is open the panel is hidden and takes no clicks (it is under the requester's input path anyway); the docked strip stays as the empty dark work area, so the screen does not move. The Screen Format requester has its own screen and no strip.
  - **Clicks never paint the picture:** `Screen::hit_test` answers `Hit::LayerPanel` for the overlay (and for the docked strip right of the screen) before the page (the title bar is hit only over the screen, part 3: the docked panel's title row lies in line with it, and its label and scroll arrows are the panel's), so the panel's gaps, title and empty rows are panel too; a stroke started on the page and dragged over the overlay goes on under it, as under the toolbox.
  - **Toggle:** **Prefs ▸ Layers** (a check item, key shown `L`) and the key **`L`** (Shift+L), on the paint screen only (not while typing text, renaming or with a requester open). Prefs, not Picture: it is a show/hide preference like Coords, it is kept in the settings file like every Prefs check item (`prefs.layer_panel`; older settings files without it leave the panel off, older builds ignore the key), and the Prefs menu already indents for check marks, so the Picture menu keeps DeluxePaint's look (a check item there would indent all of its items). `L`: DeluxePaint IV's keyboard tables (AGA p.292-296) and every key handler of the app leave Shift+L free (`l` is LightTable, Alt-`l` its Dim); it reads the physical key with Shift only, so it works on every keyboard layout, and Text tool typing, perspective mode and Magnify do not use it. No key runs a layer command (none was asked for; the panel's tooltips name no key).
  - **The active layer while the panel is off:** the title bar shows "Layer: <name>" right-aligned before the depth gadget, left of the Coords readout or the perspective angles when those show; a long name is cut and the label goes when even its start does not fit beside the program name, mode and effect flags. It shows only when the picture has more than the one visible "Background" layer (the format-3 rule), so single-layer pictures look exactly as before.
  - **Tooltips (ADR-41):** New Layer, Copy Layer, Delete Layer, Move Layer Up, Move Layer Down, Merge Down (no keys). The box goes left of the panel's column at the button's top; for the docked panel left of the toolbox, since the box is drawn on the screen. The eye boxes and rows have none.
  - **Snapshots:** `--layers-panel` shows the panel over the screen, `--layers-panel docked` docked right of it (the PNG is screen plus strip); every snapshot of a layered picture shows the title-bar name as the window does.

Its users: `compose_screen` (normal and Magnify halves, one composite per redraw), the Color Mixer's live preview, Show Page, the Light Table view. Snapshots: `snapshot_rgba`, `--show-page`, `--light-table`.

    - `menu_actions.rs`: with one visible layer on both pages Copy to Spare and Delete This Page copy the page's picture (`SetPage`, the current frame, as before); otherwise the whole picture goes over (`set_picture`, part 3). Merge in Front / Back take the spare as it shows into the active layer (in back only where the page shows colour 0).
    - `files.rs`: ILBM, PNG and ANIM export; `info`'s colour count (every layer).

    - `menu_actions.rs`: Effect ▸ Background ▸ Fix takes the active layer and remembers its number; CLR restores it on that layer only (part 3); sizes.
    - `palette_stencil.rs`: area stencils (sizes, Lock FG against the fixed background, the colour stencil Stencil ▸ Paint starts from).

    - `dpx-mcp` `lib.rs`: `describe` (size), `create_document` (a new one-layer document).

- Decided without the owner:
  - Storage as a flat list behind `Arc`s (above), `page()` = the active layer, `composite()` beside it rather than renaming `page()` (the other wave-8 branches keep compiling and keep their meaning; a missed display reader shows the active layer, a missed editing reader could not preview something different from what it commits).
  - Format version 3 for layers: the brief asked for "format_version 2", but version 2 has meant animation frames since ADR-28 and builds since then read it; a layered file under that number would fail in them with "unknown field" instead of "newer version".
  - The command names and fields above; layer numbers in every command (MCP and CLI can name any layer; the panel will mostly name the active one). Default names "Layer N" and "<name> copy". 32 layers at most. Rename accepts any name of at most 255 characters (the file format's rule since ADR-23; the bitmap font draws non-ASCII as `?`).
  - Merge Down merges regardless of visibility and keeps the lower layer's name and visibility; Flatten drops hidden layers (what shows is what stays) and keeps the bottom layer's name.
  - Deleting or moving layers can change how colour 0 looks: the layer that becomes the bottom one turns opaque, a former bottom layer moved up turns its colour 0 transparent (the owner's rule applied as stated).
  - Hidden layers can be painted (the core does not refuse); the panel does not warn (part 2).
  - Color ▸ Remap repaints every frame, not only the current one as before (the palette belongs to all frames, and the brief asks remaps to cover every layer of every frame); the remap base is forgotten on any change anyway, so all frames were drawn for it.
  - Spare page operations (part 3): Merge in Front / Back read the spare as it shows and write the active layer (Back only where the page shows colour 0); Copy to Spare and Delete This Page copy the page's picture as before when both pages have one visible layer, and otherwise the whole picture, every frame with every layer, in one undo step (`set_picture`), since the stack belongs to every frame and a page of layers cannot go into another stack. For a single-layer animation they still copy only the current frame; for a layered one, every frame (as Swap shows it). The rate stays. The spare page saved in a project is still one picture (as before).
  - The fixed background (part 3) belongs to the layer it was fixed on, by number: CLR restores it there, elsewhere CLR clears as usual (BG 0 clears an upper layer to transparent); Lock FG compares that layer whichever is active, and a fixed background whose layer is gone counts as none. Moving, adding or deleting layers below it can make the number name another layer (layers have no identity of their own). Arrange renumbers it as its layer (colour 0 stays 0 above the bottom).
  - Arrange Palette (part 3) changes nothing when the spare page (with the shown page's palette) would refuse the order, or when a fixed background on an upper layer (the page's or the spare's) uses the colour that would become 0; it is logged as every refused Arrange. The spare's fixed background is now arranged with the spare.
  - LightTable ▸ Merge (part 3): only the filled-in pixels go into the active layer; one that a layer above the active one covers, one on a hidden active layer, and colour 0 on an upper layer (BG other than 0 and another frame's colour 0) do not show afterwards.
  - Part 2: the panel's width (80 UI pixels, so a name of about 8 characters shows whole; longer ones are cut), the row and button geometry, the eye and marker artwork, the labels "Dn" and "Del" (the mockup's), the full-width Merge button; docking only in full-screen or maximized windows (the snapped window stays the picture's screen, ADR-13, instead of growing by the panel); the panel hidden under requesters; Prefs ▸ Layers and `L` (above); the panel state kept in the settings file; the title-bar label's wording and place; ghosting through engine dry runs; the right mouse button doing nothing on the panel; a click outside the rename gadget taking the name and being used up; rename limited to printable ASCII (the font's characters; the core and MCP take any name of at most 255 characters); no warning when the active layer is hidden (its empty eye box shows it; painting it works and shows once it is shown); no Flatten button.
  - Painting modes that read the page (Smear, Blend, Shade, Cycle, AntiAlias) read the active layer; on an upper layer its transparent pixels count as colour 0, not as the colours below. Flood fill and the colour stencil also see the active layer only. (Picking or filling "from all layers" is a possible later option.)
