# ADR-44: Layers, part 1: the layer model, its commands and project format version 3

- Status: accepted (2026-11-12, wave 8; the owner decided that layers are built now, see Owner decisions; the points under "Decided without the owner" were not asked). Part 2, the layer panel at the right edge with its key and menu item, follows in its own change.
- Context:
  - Since ADR-28 a document is 1..N animation frames of one size, one palette and one target, each frame one indexed page; the current frame is "the page" every page command paints. `docs/ARCHITECTURE.md` planned a layer tree; nothing was built. The owner's MCP and image-generation specification asks for layers (`list_layers`, `create_layer`, `select_layer`, generated pictures as a new layer) and the owner decided to build them now.
  - DeluxePaint IV AGA has no layers (its Spare page and stencils are the nearest things). This is a DeluxePainter addition; it follows the frame model of ADR-28 wherever there is a choice.
- Owner decisions (wave 8, binding):
  - Layers are built now. A layer panel at the right edge, toggled by a key and a menu item (part 2).
  - On every layer above the bottom one palette colour 0 is transparent: painting with colour 0 erases there.
  - Layers are only visible or hidden (no % opacity). No layer groups yet.
  - A generated picture's target is Spare page / Picture / Brush; "New layer" comes with the integration step.
- Decision:
  - **Model (`dpx_core::Document`, `dpx_core::layer`):** one layer stack per document, shared by every frame: `Layer { name, visible }`, bottom first; layer 0 is the bottom layer ("Background" in every new document). Every frame holds one indexed picture per layer, all of the page size, all in the document palette and target. The document has an active layer. `Document::page()` is the active layer of the current frame, so every page command (strokes, shapes, fills, CLR, Flip, BG->FG, BG<->FG, SetPage, MergePage, Stenciled, AnimBrushPaint) paints it unchanged; `frame(i)`/`frames()` are the active layer of each frame (the AnimBrush pick-up and Anim ▸ Move paint and read them). New accessors: `layers()`, `layer_count()`, `active_layer()`, `layer(l)` (current frame), `cel(f, l)`, `cels()` (every picture), `from_layers(..)`.
  - **Storage:** the page plus every other picture behind an `Arc`, frame by frame and bottom layer first (`others`); a single-layer document keeps exactly the list it had before (its other frames), so its undo snapshots and byte counts are unchanged. Selecting a layer or a frame moves the page in and out of that list (`Document::focus`). A new layer is one clear picture shared by every frame, a duplicate shares the copied pictures; a picture is copied when it is painted.
  - **Transparency and the composite:** above the bottom layer colour 0 is transparent; the bottom layer is opaque. `Document::composite()` / `composite_frame(i)` / `composite_frames()` give a frame as it looks: its visible layers bottom to top (`layer::flatten`); the lowest visible layer is copied as it is (over a hidden bottom layer an upper layer's colour 0 shows colour 0, the colour of an empty page), nothing visible gives colour 0. With one visible layer (every single-layer document) the composite is that layer itself, borrowed (`Cow::Borrowed`), so single-layer documents show and export bit-identical to before without a copy. `composite_with(img)` / `composite_frame_with(i, img)` put a stroke preview in the active layer's place.
  - **Commands (JSON `op`, layer numbers from 0 = bottom):** `add_layer {name?}` (a transparent layer above the active one, which becomes active; default name "Layer N", the smallest N unused), `duplicate_layer {layer}` (above it, name + " copy", same visibility; the copy becomes active), `delete_layer {layer}` (never the last; the layer below becomes active when the active one goes, the new bottom layer when the bottom one goes), `move_layer {from, to}` (the others close up; the active layer stays the same layer), `select_layer {layer}`, `set_layer_visible {layer, visible}`, `rename_layer {layer, name}` (at most 255 characters, the project format's limit), `merge_layer_down {layer}` (layer >= 1: its pixels other than colour 0 cover the layer below in every frame, shown or hidden; the result keeps the lower layer's name and visibility), `flatten_layers` (every frame becomes one layer showing what it shows, hidden layers go; it keeps the bottom layer's name and is visible). At most 32 layers (`layer::MAX_LAYERS`).
  - **History:** every layer command is one undo step, except `select_layer`, a setting like `goto_frame` (no undo step, the revision counts, the redo list stays). Undo steps remember the active layer as they remember the frame (ADR-28): undoing or redoing a pixel step of another layer selects that layer first, and the outcome names the whole page. Footprints: add, duplicate, delete, move, merge and flatten snapshot the document (`Footprint::Layers`; the pictures are shared, only what the step keeps alive counts for the byte budget); visibility and rename keep only the names and flags (`Footprint::LayerInfo`). The outcome of every layer command names the whole page (what it shows may change); palette and format are unchanged.
  - **Commands that touch every picture:** Screen Format without Retain clears the page to one "Background" layer (all frames, the active layer 0); with Retain every layer of every frame takes the new size and the colours of every layer count for the palette size. Page Size gives the new area the BG colour on the bottom layer and colour 0 (transparent) above it. Frame commands (Set #, Add, Copy, Insert copies, Delete) copy, move and delete a frame with all its layers; deleting every frame leaves one frame with the bottom layer in BG and the upper layers clear. Arrange Palette renumbers every layer of every frame and keeps colour 0 at 0 above the bottom layer; an order that would make another colour entry 0 is refused (`PALETTE_RANGE_INVALID`) when an upper layer uses that colour, since it would turn transparent there. Color ▸ Remap is now the command `remap_colors {from}`: every layer of every frame is repainted (nearest colour), and above the bottom layer colour 0 stays 0 and no other colour becomes 0. SetPage of another size is refused with more than one layer (as with more than one frame).
  - **Limits:** frames times layers times page pixels must stay within ADR-28's 128 MiB (`anim::max_frames_for_layers`; the frame requesters' maxima follow it). With one layer at least one frame is always allowed, as before; with more, a frame of that many layers must fit. The project reader's entry limit becomes 999 frames x 32 layers + 2 = 31 970 so every document the program allows can be read back.
  - **Project format version 3** (`docs/PROJECT_FORMAT.md`): written when the stack is not the one visible "Background" layer (more than one layer, or one renamed or hidden layer): the version-2 fields plus `layers` (name, visible, bottom first) and `active_layer`, and `frames/<n>/layers/<k>.png` per layer, the frame entries naming their layers in stack order. Everything else is written exactly as before (version 1, or 2 for animations), byte for byte, so single-layer projects still open in older builds; older builds refuse a layered project as "from a newer version" instead of dropping layers. The reader takes versions 1, 2 and 3; a version-1/2 file's layer keeps the name its frames give it (DeluxePainter always wrote "Background").
  - **Exports and the CLI:** ILBM, PNG and ANIM hold what the frames show, the composite (`files::encode_document`, MCP `pictures::encode_document`; there is no HAM or EHB writer yet: an EHB picture saves as a 64-colour ILBM through the same path, ADR-26). With more than one layer, or a hidden one, the save notes it ("3 layers saved as one picture, as shown, 1 hidden layer left out (save as .dpxproj to keep them)"). `.dpxproj` keeps every layer and notes nothing. `info` lists the layers of a project that has more than the default one and counts the colours of every layer; `convert` goes through the document and so flattens like Save.
  - **Autosave and recovery** (ADR-34) write and read the same project format, so they keep every layer, the active layer and the current frame.
  - **MCP (headless):** `get_pixels` and `render_png` read the composite of the current frame; `save_picture` exports the composite with the note; the hardware check looks at every layer. `execute_command` accepts the layer commands as it accepts every `Command`. No layer tools and no layer fields in `get_document_state` yet (integration step).
- Reader audit (every caller of `Document::page`, `frame`, `frames` outside dpx-core, found by marking the three methods deprecated and building every target; tests left out):
  - **Composite (shows or writes the picture):**
    - `main.rs`: `PainterApp::page()` is now the picture as shown (`Cow`): the Light Table or playback picture, the perspective view, else the current frame's composite with the stroke preview in the active layer's place. Its users: `compose_screen` (normal and Magnify halves, one composite per redraw), the Color Mixer's live preview, Show Page, the Light Table view. Snapshots: `snapshot_rgba`, `--show-page`, `--light-table`.
    - `anim.rs`: `light_table_page` takes the other frames' composites and the spare's composite; playback shows `composite_frame`.
    - `anim_control.rs`: the Move preview frame.
    - `perspective.rs`: the brush is stamped into a copy of the active layer, that copy is composited, the wire frame and cross hairs go on top.
    - `palette_stencil.rs`: the Stencil ▸ Paint / Show view's picture (and the Brush Selector frame through `composite_with`), the spare in its Light Table, `--stencil-paint`.
    - `menu_actions.rs`: Copy to Spare takes the shown picture (into the spare's active layer); Merge in Front / Back and Delete This Page take the spare as it shows (into the active layer).
    - `files.rs`: ILBM, PNG and ANIM export; `info`'s colour count (every layer).
    - `dpx-mcp`: `view::get_pixels`, `view::render_png`, `pictures::encode_document` (ILBM, PNG, ANIM), `validate_hardware` (every layer).
    - `dpx-formats` `project::write_project`: every layer of every frame.
  - **Active layer (paints, picks up or measures):**
    - `tools.rs`: stroke, shape, fill and text previews (`preview` copies, `redraw`, `add_part`, `check_paint`), the Brush Selector pick-up, Magnify's page size.
    - `main.rs`: `--pick`; sizes for scrolling, the pointer, Page Size and Screen Format.
    - `animbrush.rs`: the AnimBrush pick-up (its transparent colour and `anim_brush::pick_up`, active layer of each frame).
    - `anim.rs`: LightTable ▸ Merge paints the shown images into the active layer through its BG pixels (`SetPage`).
    - `menu_actions.rs`: Effect ▸ Background ▸ Fix and CLR on a fixed background (the active layer); sizes.
    - `palette_stencil.rs`: area stencils (sizes, Lock FG against the fixed background, the colour stencil Stencil ▸ Paint starts from).
    - `perspective.rs`: Replace mode reads the active layer; bounds.
    - `import.rs`: sizes; Import Ok replaces the document (one layer).
    - `dpx-mcp` `lib.rs`: `describe` (size), `create_document` (a new one-layer document).
  - **Every picture:** `files::page_at_least_screen` (every layer of every frame grows), Color ▸ Remap (`remap_colors`), the project writer and reader.
- Decided without the owner:
  - Storage as a flat list behind `Arc`s (above), `page()` = the active layer, `composite()` beside it rather than renaming `page()` (the other wave-8 branches keep compiling and keep their meaning; a missed display reader shows the active layer, a missed editing reader could not preview something different from what it commits).
  - Format version 3 for layers: the brief asked for "format_version 2", but version 2 has meant animation frames since ADR-28 and builds since then read it; a layered file under that number would fail in them with "unknown field" instead of "newer version".
  - The command names and fields above; layer numbers in every command (MCP and CLI can name any layer; the panel will mostly name the active one). Default names "Layer N" and "<name> copy". 32 layers at most. Rename accepts any name of at most 255 characters (the file format's rule since ADR-23; the bitmap font draws non-ASCII as `?`).
  - Merge Down merges regardless of visibility and keeps the lower layer's name and visibility; Flatten drops hidden layers (what shows is what stays) and keeps the bottom layer's name.
  - Deleting or moving layers can change how colour 0 looks: the layer that becomes the bottom one turns opaque, a former bottom layer moved up turns its colour 0 transparent (the owner's rule applied as stated).
  - Hidden layers can be painted (the core does not refuse); the panel may warn.
  - Color ▸ Remap repaints every frame, not only the current one as before (the palette belongs to all frames, and the brief asks remaps to cover every layer of every frame); the remap base is forgotten on any change anyway, so all frames were drawn for it.
  - Spare page operations read the spare as it shows and write the active layer; the spare page saved in a project is still one picture (as before).
  - Painting modes that read the page (Smear, Blend, Shade, Cycle, AntiAlias) read the active layer; on an upper layer its transparent pixels count as colour 0, not as the colours below. Flood fill and the colour stencil also see the active layer only. (Picking or filling "from all layers" is a possible later option.)
- Verified (unit and app tests, CI gate):
  - `dpx-core`: flatten rules; names and limits; every command and its undo, including the active layer after add / duplicate / move / delete and undo back to the start; colour 0 erases above the bottom layer; visibility, rename, merge down, flatten and their JSON; undo and redo go back to the painted layer; frame commands carry every layer; Page Size and Screen Format on every layer (and Screen Format without Retain resetting to one layer); Arrange Palette keeping colour 0 transparent and refusing a conflicting order; the memory limit with frames and layers; layer steps sharing pictures within the byte budget; `Document` storage invariants while the page moves over frames and layers; the composite borrowing the page for one visible layer; `from_layers` checks.
  - `dpx-formats`: a 4-frame, 3-layer project (one hidden layer, frame 3 and layer 2 current) round-trips with every picture, the stack and the active layer identical and the bytes deterministic; one renamed or hidden layer gives version 3; version-3 rules (missing fields, active layer, too many layers, a frame without all layers, a misnamed entry, a missing picture, frames times layers over the limit before decoding); version-1/2 rules unchanged; single-frame projects still version 1 byte for byte.
  - `dpx-mcp`: `get_pixels` and `render_png` show the visible layers (and stop showing a hidden one); ILBM, PNG and ANIM saves hold the composite of every frame with the note.
  - App (`composite_tests`, through the real `ui()` loop where the screen shows): the screen shows every visible layer; a freehand drag on the upper layer previews over the bottom layer and commits to the upper layer only; colour 0 erases to the bottom layer; hiding a layer and `U` (undo) show on screen; Magnify, the Light Table and `page()` show the composite; a single-layer page is borrowed, not copied; ILBM, PNG and ANIM files written by Save hold the composite and say so, `.dpxproj` keeps every layer silently; the recovery project keeps frames, layers and the active layer; a small layered picture grows to the screen on every layer; Remap repaints every frame and layer and keeps colour 0 transparent.
  - Snapshots (real renders, `deluxepainter --snapshot`): `docs/design/screenshots/wave8-layers.png` from `wave8-layers.json` (layers Sky, Hills with a hole erased in colour 0, Sun, and a hidden red layer that does not show); `wave8-layers-light-table.png` from `--frames 2 --commands wave8-layers-light-table.json --frame 2 --light-table previous,dim` (frame 1's moon, on the third layer, dimmed behind frame 2).
  - CLI (macOS, debug build): a version-3 project written by an independent Python script (2 frames, 3 layers, one hidden) is described by `info` with its layers, converts to PNG and ANIM with the flatten note, and to `.dpxproj`, whose re-save is byte-identical. The headless MCP server over stdio: `add_layer`, a rectangle on it, `get_pixels` gives the composite, `set_layer_visible false` hides it again.
  - Timings (`composite_timing`, ignored test, Apple Silicon, 4 layers): 320x256 0.14 ms (release) / 0.19 ms (dev profile); 1008x1024 2.1 / 2.4 ms; 4096x4096 30 / 39 ms. The screen makes one composite per redraw of a layered page (none for a single layer).
- Not verified: the GUI by hand (no layer UI exists before part 2; the snapshot and the ui-loop tests drive the real composing code), other operating systems, real MCP clients, very large layered animations near the 128 MiB limit in the GUI.
- Open for part 2 and the integration step:

  - The fixed background (Effect ▸ Background ▸ Fix) is one picture taken from the active layer; CLR restores it into whatever layer is active. Per-layer fixed backgrounds are a part-2 decision.
  - Composite only the visible rectangle if 4096x4096 layered pages must redraw faster than about 30 ms.
  - Integration: MCP layer tools and state (`TODO(wave8-integration)` in `crates/dpx-mcp/src/lib.rs`), the layer ops in `execute_command`'s description, "New layer" as a target for generated pictures, and the image-generation command that replaces the whole picture must reset to one layer (as Screen Format without Retain does: `Document::set_layered` with `Layer::background()`).
