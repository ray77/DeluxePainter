# ADR-36: AnimBrush and Metamorph

- Status: accepted (Phase 4, 2026-11-11, wave 7; every point marked "decided without the owner" is open for the owner to change)
- Context:
  - DeluxePaint IV AGA has a brush made of several cels. Every stamp paints the current cel and moves on to the next one, so a stroke or a row of clicks shows an animation (reference p.249–252, tutorial p.164–167, Appendix B p.292–293 and p.296). Until now DeluxePainter had only the single custom brush (ADR-18/19/30). Anim ▸ AnimBrush and Brush ▸ Spare ▸ Metamorph.. were ghosted.
  - Manual facts used here, in our own words:
    - Pick up: the Brush Selector takes the cels from the current frame on, one per frame. In the tutorial the box is dragged first and then a requester asks for the number of cels; picking up on frame 1 of 20 suggests 20 (p.164). A single frame cannot be picked up as an AnimBrush (p.250). Alt held with the Brush Selector does the same as the menu item (p.250).
    - Settings (figure 8.28, p.251): Number of cels (information), Duration, Current cel and three Direction buttons (forward, backward, ping-pong). Duration is the number of stamps the brush needs to go through its cels once. Fewer stamps than cels skip cels, more repeat them. Ping-pong goes there and back, so 11 cels take 20 stamps (p.167).
    - Use makes the last AnimBrush the brush again, Free discards it, and a right-click on the Brush Selector switches between the custom brush and the AnimBrush (p.251). `B` restores the last custom brush or AnimBrush (p.293). `7` / `8` step to the previous / next cel, Shift+`7` / Shift+`8` jump to the first / last cel (p.296).
    - Brush transforms act on every frame of an AnimBrush (Flip, p.244). Load and Save use their own file requesters, and loading keeps the picture's palette (p.249).
    - Metamorph (p.243, key Alt+`m`) needs a custom brush and a spare brush and asks for the cel count in a "Make AnimBrush" requester. Brushes of the same size give the best result, and the first and last cels may differ a little from the brushes. The AGA addendum (p.11–12) says the morph goes from the current brush to the spare brush. Swapping them first with Alt+`b` (Brush<->Spare) reverses it. Appendix B (p.292) still has the older wording "from spare to current"; the addendum is the AGA behaviour.
    - The AGA addendum (p.11) gives a size formula for 256-colour AnimBrushes. DeluxePainter keeps its own byte limit per document instead (below).
- Decision:
  - **Core (`dpx-core::anim_brush`)**: `AnimBrush { cels, duration, direction, clock }`, 2..=999 cels (`MIN_CELS`, `MAX_CELS` = the frame limit), duration 1..=999, all cels together at most `MAX_FRAME_BYTES`. The clock is a cel step plus a remainder. Stamp `k` after the clock shows cel `direction.cel((step + (sub + k·n) / duration) mod period)`, where period is `n` (forward, backward) or `2n − 2` (ping-pong). The default duration is `n`, which gives one cel per stamp. The Settings keep the current cel when duration or direction change. `pick_up(doc, rect, cels, transparent)` takes the box from the current frame on and wraps to frame 1 after the last frame (cel count 2..=frames), with the handle in the centre.
  - **One command engine**: `Command::AnimBrushPaint { brush, paint }` wraps a custom-brush `Stroke` or `Shape` (JSON op `anim_brush_paint`, so the CLI `--commands` and MCP get it too). The stamper counts every stamp, also those clipped off the page, so a stroke painted in parts (the app's freehand preview) equals the whole stroke when each part starts from the clock after the previous part. Symmetric copies show the original's cel at each stamp. `Command::stamps()` gives the count the app moves the clock on by. Validation checks every cel against the palette and limits, and the work estimate uses the most expensive cel. One stroke is one undo step. Undo does not move the clock back (decided without the owner: DeluxePaint's clock is not part of the picture either).
  - **Metamorph (`anim_brush::metamorph`)**: both brushes sit on one canvas, the union of their extents around the handle. For cel `i` of `n`, `t = i/(n−1)`, and the content box is interpolated between the two brushes' boxes. Both brushes are scaled into it. Their signed distance fields (8SSEDT nearest-site propagation) are mixed as `(1−t)·dA + t·dB`, and negative means painted. Each painted pixel gets the palette colour nearest to the RGB mix of the two brushes' nearest painted colours, never the transparent colour. The first and last cels are exactly the two brushes. Deterministic, no randomness.
  - **Files (`dpx-iff::anim`)**: an AnimBrush is saved as an IFF ANIM. There is one frame per cel, with the cels padded to one canvas around a common handle. The first picture carries the transparent colour (BMHD masking 2) and the handle (GRAB), and there are no closing loop frames. `EncodeOptions` gained `transparent` and `grab`, and `Anim` reports both when reading (masking 2 or 3). Duration, direction and current cel are not stored, so a loaded AnimBrush has the defaults (decided without the owner: the DeluxePaint file layout for them is unknown to us). Loading refuses ANIMs with fewer than 2 frames. Cel colours are fitted to the picture palette where the palettes differ (Color ▸ Brush ▸ Remap logic), and the note "AnimBrush loaded" then says how many colours changed. ANIM is an existing export format, so no new output format is added.
  - **App (`apps/deluxepainter/src/animbrush.rs`)**: menu ids `animbrush.pick_up`, `animbrush.use`, `animbrush.free`, `animbrush.load`, `animbrush.save`, `animbrush.settings`, `brush.metamorph` (one `// ADR-36` block in `IMPLEMENTED` and one dispatch arm in `run_action`). Save, Settings, Use and Free are ghosted without an AnimBrush. Metamorph is ghosted without both a custom brush and a spare brush.
    - "In use" is a flag of the AnimBrush state. Making, loading, Use, `B` and the right-click back set it. A plain pick-up, Brush ▸ Load.., Brush ▸ Restore of the picked-up brush, a built-in brush, Alt+`b` (Brush<->Spare), the right-click away and Free clear it, also when that brush looks exactly like the current cel (cel 1 of a Metamorph of same-size brushes is the brush itself). As a guard, the custom brush must also be the current cel, so no other path that replaces the brush can make a stroke paint the cels. The AnimBrush is kept when another brush is chosen. A new gesture paints through `AnimBrushPaint`, and after the commit the clock moves on by its stamps, so the next stroke, on this frame or another, goes on from there. If a cel no longer fits the palette (after a Screen Format with fewer colours), the current cel paints as a plain brush.
    - Color ▸ Palette ▸ Arrange renumbers every cel (pixels and transparent colour), the brush the AnimBrush was made after and the Any Angle originals with the same table as the custom brush (`AnimBrush::renumber`, `anim_brush::renumber_cel`), so the AnimBrush stays in use, looks the same and `B` still finds it (ADR-31: everything that holds colour numbers follows an Arrange).
    - Size limit: all cels together hold at most `MAX_CEL_BYTES` (128 MiB, the frame limit). Make AnimBrush allows at most `anim_brush::max_morph_cels` cels (the limit divided by the union canvas of brush and spare brush; the requester then shows "2 to N"). When not even two cels fit, Metamorph shows the note "AnimBrush too big" instead of the requester, and `metamorph` itself refuses more cels before doing any work. The instant transforms and drag gestures on every cel use `AnimBrush::map_within`, which stops at the first cel over the limit; the AnimBrush then stays as it was and the same note says why (for one brush, Double at the side limit stays silent, ADR-30).
    - Pick up..: arms the Brush Selector once. The box is dragged, then the "Pick up AnimBrush" requester asks for Number of cels (2 to the number of frames). The suggestion is the frames from the current one to the last, or all frames on the last frame. Alt held while the box is let go does the same. One frame: the note "No AnimBrush" says to add frames first.
    - Settings..: the "AnimBrush Settings" requester (Duration, Current "of N", three direction buttons drawn in our own pixel style, square corners).
    - Use / `B` / right-click on the Brush Selector: Use always brings the AnimBrush back. `B` does so while the AnimBrush is newer than the last picked-up brush, otherwise it restores that brush as before. Brush ▸ Restore (whose key is `B`) does the same and is not ghosted while `B` would bring back the AnimBrush, also before any plain brush was picked up. The right-click switches from the AnimBrush to the last picked-up brush (or the built-in brush), and from any other brush back to the AnimBrush. Free discards it; if it was in use, the built-in brush follows.
    - Keys: `7` / `8` previous / next cel (wrapping, repeating while held), Shift+`7` / Shift+`8` first / last cel, only while the AnimBrush is in use. The digit keys count by their place on the keyboard (egui's physical key), so Shift works on every layout. Alt+`m` Metamorph, Alt+`n` Brush->Spare and Alt+`b` Brush<->Spare follow the menu's ghosting.
    - The instant Brush transforms (flip, rotate 90°, halve, double, outline, trim, handle, BG->FG, swap, transparency, remap) and the drag gestures (Stretch, Any Angle, Shear, Bend, Place) change every cel the same way while the AnimBrush is in use. A second Any Angle starts again from the cels before the first one, as ADR-30 does for one brush.
    - Make AnimBrush (Metamorph): the cel count suggestion is the number of frames, or 8 on a single frame (at most the cels that fit the size limit). The new AnimBrush becomes the brush in Matte mode. The cel count requesters are wide enough for the form's "must be 2 to N" message.
  - Snapshots: `--animbrush-requester pick|make|settings` shows the three requesters headless.
  - Not part of ADR-36: animpainting with Alt held while drawing (p.296; it paints across frames and belongs with Anim ▸ Method/Move). Picking up with the right button never cuts the AnimBrush out of the frames.
- Decided without the owner (all visible except where noted):
  - Pick-up order for both the menu item and Alt: drag the box first, then the requester (the tutorial order; the reference text can be read either way).
  - Metamorph goes from the current brush to the spare brush (AGA addendum), not "spare to current" as in Appendix B and in the task text. Alt+`b` reverses it.
  - The `B` rule (AnimBrush only when made after the last picked-up brush) and the right-click toggle targets.
  - The Make AnimBrush suggestion (frames, else 8) and the Pick up suggestion on the last frame (all frames).
  - `7` / `8` act only while the AnimBrush is the brush. They step in cel order whatever the direction.
  - On German keyboards Shift+`7` also types `/`, which still switches the Symmetry tool (the existing `/` key). Both happen. Not changed here because `/` is an existing key.
  - Saved AnimBrush files keep cels, transparency and handle, not duration or direction (internal).
  - Undo leaves the cel clock where it is (internal).
  - Alt+`b` while the AnimBrush is in use puts its current cel into the spare brush as a plain brush; swapping back gives that plain brush, not the AnimBrush (the spare holds one brush; Use, `B` or the right-click bring the AnimBrush back).
  - Too big: Make AnimBrush caps the cel count at what fits 128 MiB, and a transform that would pass the limit leaves the AnimBrush unchanged with the note "AnimBrush too big" (DeluxePaint's own limit was the Amiga's memory; its message is not known to us).
- Verified:
  - Unit tests (dpx-core): cel sequences per stamp, duration spreading and skipping, forward, backward and ping-pong (11 cels → 20 stamps), settings keep the current cel, pick-up from the current frame with wrapping, transforms and remap on every cel, one canvas for files, metamorph start and end cels exact, deterministic, never the transparent colour, nearest-site field, `AnimBrushPaint` one undo step and JSON round trip, a stroke painted in parts equals the whole stroke, symmetric copies show the original's cels, stamp counts, bad AnimBrushes refused (duration 0, no cels, colour outside the palette, wrapping a non-paint command, work estimate), and cels following clipped stamps in the raster stamper.
  - Unit tests (dpx-iff, dpx-ui): transparent colour and GRAB survive an ANIM round trip. The three requesters: cel range, editing, direction buttons, rendering. Menu ghosting for every new id.
  - Review fixes (unit tests): `map_within` stops at the first cel over the limit and keeps settings and clock; `renumber` keeps every cel's look; `max_morph_cels` (8192x8192 canvas: 2 cels, 8193x8193: 1, 1000x1000 brushes: 134) and `metamorph` refusing more before any work; the Make requester's maximum and message width. App tests through `ui()`: Color ▸ Palette ▸ Arrange through the menu with a swatch drag (the AnimBrush stays in use, looks the same, `B` still finds it, two clicks stamp cels 1 and 2 in the old colours); Alt+`m` with brushes 8193 pixels apart (note, no requester), Alt+`m` with 1000x1000 brushes refusing 135 cels, an Ok for 999 cels refused with the note; Brush ▸ Size ▸ Double on 33 cels of 1024x1024 and a Shift-Stretch drag of 400 cels of 1024x1 left unchanged with the note; a Metamorph of same-size brushes whose cel 1 is the picked-up brush: the right-click goes to the plain brush (a click paints it and leaves the clock), the second right-click comes back, a plain pick-up of the same brush and Alt+`b` twice leave the AnimBrush; Brush ▸ Restore enabled and working through the menu with no plain brush picked up. Each of these app tests failed with its fix reverted.
  - App tests drive `PainterApp::ui` with real egui pointer and key events: Alt-drag with the Brush Selector (requester, Return, 3 cels from frame 2 on, no cut, tool restored, plain pick-up afterwards); Pick up.. through the held right-button menu, Esc, armed once only, the one-frame note from the menu and from Alt; `7`, `8`, Shift+`7`, Shift+`8`, held `8`, and Shift+`8` reported as another key; clicks that stamp cel after cel, Undo, `2` to the next frame and on, and a continuous freehand stroke that equals the reference `AnimBrushPaint` with the right clock; right-click on the Brush Selector both ways, `B` in both cases, Use and Free through the menu with ghosting after; the Settings requester through the menu (arrow keys, Tab, a click on the ping-pong button, Return); Alt+`n`, Alt+`m` (Make AnimBrush, arrow keys, Return), Alt+`b` and Brush ▸ Spare ▸ Metamorph.. through the menu with the reversed result, and Alt+`m` without a spare doing nothing; flip, double and a Stretch drag on every cel; Save and Load through the menu into a temporary directory (overwrite question, palette fitting with its note, single-frame ANIM refused).
  - Snapshots looked at: the three requesters, the Anim ▸ AnimBrush submenu (ghosting), a screen with a 10-cel morph stamped by 20 clicks through the real pointer, and a CLI `--snapshot --commands` run with a ping-pong `anim_brush_paint` (cels 1, 2, 3, 2, 1, 2, 3, 2).
  - Gate: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`.
  - Snapshots looked at after the review fixes: the Make AnimBrush requester for two 1000x1000 brushes refusing 135 ("2 to 134", the message fits) and the "AnimBrush too big" note.
  - Not verified: a real window with a real keyboard (German or US layout), AnimBrush files written by DeluxePaint itself (`.anbr` samples were not tried), and how closely the morph matches DeluxePaint's own in-between shapes. Known: a Make AnimBrush near the size limit still runs on the UI thread and takes seconds (a reviewer measured 12.5 s in a release build for 140 cels of 1000x1000).
