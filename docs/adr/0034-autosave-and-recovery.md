# ADR-34: Autosave and crash recovery

- Status: accepted (Phase 4, 2026-11-11; decided without the owner, FEATURES P1 "Autosave & crash recovery")
- Context:
  - A crash or a power cut lost all work since the last Save. DeluxePaint IV has no recovery; its Quit "asks to save if modified" (manual-ui-notes, Quit, AGA p.38/p.242).
- Decision:
  - **Unsaved** = the engine revision differs from the revision at the last Save or Load. Undo also bumps the revision, so undoing back to the saved state still counts as unsaved (conservative: at worst one extra recovery file). A Save to `.dpxproj` or a Load marks the picture clean; Export and animation saves do not (they are not the lossless working file).
  - **Autosave:** while unsaved, a recovery project (`encode_document` to a `.dpxproj`, written atomically) is written after **30 s without a change**, or after 120 s of steady changes (so continuous drawing is still covered). It is written again on quit with unsaved changes. Only the GUI does this: snapshot, CLI and MCP never autosave, and tests attach no store unless they give one a temp directory.
  - **Where:** `<data dir>/recovery/recovery.dpxproj` plus `recovery.json` (original picture path, time). Data dir from std and the environment, no extra dependency: macOS `~/Library/Application Support/DeluxePainter`, Windows `%APPDATA%\DeluxePainter`, elsewhere `$XDG_DATA_HOME` or `~/.local/share/DeluxePainter`. `DELUXEPAINTER_DATA_DIR` overrides it. Nothing is written elsewhere, never next to the owner's pictures.
  - **One slot:** one recovery file, always the current picture. The program has one document window and one picture at a time, so older slots would only be stale copies; the owner is asked once at start and the answer empties the slot.
  - **Deleted** on a clean Save, on Load, and on a normal quit without unsaved changes. While the Recover Picture question is open (the file is still waiting for an answer) quitting leaves it alone.
  - **At start**, if the slot holds a project: a modal "Recover Picture" requester (pixel UI, our own layout like the note requester) names the picture and the autosave time (UTC; std has no local time zone) with **Recover** (Return) and **Discard** (Esc). Recover opens it like Load: the picture name is restored and the picture stays unsaved; the slot is kept (rewritten) until the owner saves. Discard deletes it. A file that does not load is deleted and a note "Recovery discarded" explains; no crash.
  - **Quit with unsaved changes** (Picture ▸ Quit, window close button, Cmd+Q) asks "Quit without saving?" with Yes / No. Return and Esc mean No (the safe answer). Yes quits and writes the recovery file, so nothing is really lost. DeluxePaint asks to save; DeluxePainter does not offer Save in that question (Yes/No as the owner specified), the recovery file covers it.
  - `ChoiceRequester` in `dpx-ui` is the shared two-button requester.
- Verified: unit tests with temp data directories (autosave only after the idle time and restarted by a change, the 120 s cap, deleted after Save but not after Export, quit asks and answers, recover round trip with identical project bytes and still unsaved, discard, damaged file at start and at answer time, no store = no writes), requester tests, UTC formatting; screenshot `docs/design/screenshots/phase4-recover.png` (`--snapshot ... --recover-requester`). Not tried: a real crash or kill in the window, the close button and Cmd+Q, Windows/Linux paths.
