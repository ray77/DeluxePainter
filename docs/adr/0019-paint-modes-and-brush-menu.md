# ADR-19: Paint modes in `plot` and the Brush menu

- Status: accepted (wave 2, 2026-11-10)
- Context: ADR-18 added `BrushImage`, `DrawMode` and `paint::plot`, but only Matte, Color and Replace did anything, and the Brush menu was ghosted. Mode details come from `docs/research/manual-ui-notes.md` (sections 2.2 and 5).
- Decision:
  - **Modes in `paint::plot`** (signature unchanged; stencil check first; the source pixel is read from `ctx.before`, so a gesture moves a pixel at most one step; a mode with nothing to do leaves the pixel):
    - Matte / Color / Replace: set the pixel to `color`.
    - Shade: a pixel whose colour is in `ctx.range` moves one index up (right button: down), clamped to the range; outside the range or without a range it is unchanged.
    - Cycle: like Shade but wraps within the range. Without a range it paints plain `color` (notes: "if FG is in no range paints plain FG"); pixels outside a given range are unchanged.
    - Blend: nearest palette colour to the 50 % RGB mix of the page pixel and `color`.
    - Mix: the manual's availability text is garbled, so Mix is Blend weighted 25 % brush / 75 % page (documented guess).
    - Smooth: nearest palette colour to the average RGB of the 3x3 neighbourhood in `before` (pixels off the page are left out).
    - Smear: takes the colour at `(x - motion.0, y - motion.1)` on the current page; unchanged when that is off the page or the brush has not moved.
    - HBrite: index < 32 becomes index + 32 when the palette has 64 entries, else unchanged.
  - **`dpx_core::brush_ops`**: pure functions on `BrushImage`, each returning a new brush with its handle following the pixels: flip horizontal/vertical, rotate 90 (clockwise), double (both / horizontal / vertical), halve (each 2x2 block becomes its first opaque pixel), outline (grows 1 px per side, 8-neighbour ring in FG; without a transparent colour the whole ring), trim (removes the outermost layer of opaque pixels, i.e. those touching a transparent pixel or the edge, and crops; the inverse of outline; `None` when nothing is left), BG -> FG (transparent pixels untouched), BG <-> FG (the transparent colour swaps with them), Change Transparency (transparent colour = BG), Handle Center and Corner (centre, top left, top right, bottom right, bottom left, centre, as the AGA addendum's five positions).
  - **`apps/deluxepainter/src/brush_menu.rs`** wires `brush.*` ids to `custom_brush`; Restore sets `custom_brush = picked_brush`. Brush files are IFF ILBM with BMHD masking 2 (transparent colour), the handle in GRAB and the palette in CMAP. Loading fits brush colours that differ from the picture palette to the nearest picture colour (the picture palette stays; a note says how many) and sets both `custom_brush` and `picked_brush`; a mask plane (masking 1) becomes an unused colour used as transparent colour. New `FileKind::LoadBrush` / `SaveBrush`.
  - **Ghosting**: `MenuContext` has `has_brush` and `can_restore` (kept in sync from `PainterApp` at the start of every frame through `UiState`). Without a custom brush every brush item except Load.. is ghosted; Restore needs a picked-up brush.
  - Still ghosted (interactive, not done): Stretch, Rotate Any Angle, Shear, Bend Horiz/Vert, Handle Place, Remap (a `BrushImage` has no palette of its own), Spare, Metamorph, Brush -> Spare / Spare swap. Rotate 180/270 are not menu items.
- Deviations from DPaint IV: Mix is a guess (above). Outline also paints holes inside the brush that touch opaque pixels, and trim erodes them again only at the border. Brush files do not store colour ranges (CRNG). Brush colours are fitted to the picture palette on load, not kept as the brush's own palette (no "Use Brush Palette" yet). Halve picks pixels instead of averaging.
- Verified: unit tests for every mode, every `brush_ops` function (size, handle, pixels), Brush menu actions through `run_action`, the ghosting flags, and a save/load round trip through the file requester; `cargo fmt`, `clippy -D warnings` and `cargo test --workspace` pass. `docs/design/screenshots/phase3-modes.png` was rendered by the `mode_demo` test (set `DPX_MODES_PNG=path`): panels left to right, top then bottom: original bars, Smear, Shade, Blend, Cycle, Smooth, Mix, HBrite, each with one diagonal stroke of a round brush.
- Not verified: the modes and the Brush menu in the running GUI (the tools do not call `plot` with a custom brush yet, wave 2 wiring); brush files against real DeluxePaint brush files; Mix against the original.
