# ADR-32: IFF ANIM files in the app

- Status: accepted (Wave 5, 2026-11-10; internal decisions taken without the owner, as CLAUDE.md allows)
- Context: the codec (ADR-29) and animation frames (ADR-28) exist; this wires them together in the GUI, `info`, `convert` and MCP.
- Decision:
  - **Shared glue** in `dpx_iff::anim_doc` (used by the app and MCP): `content_of(&Anim)` and `holds_for_fps`.
  - **Load**: Picture ▸ Load.. and Anim ▸ Load.. (`anim.load`, requester "Load Animation", same loader) open a `FORM ANIM` as a multi-frame document: frames = the logical frames (the two closing loop frames dropped), palette from the first frame, CRNG kept, display mode from CAMG and size and the screen from the picture size (ANIM has no page fields), current frame 1. A file with more frames than a document holds (ADR-28 limits) opens its first frame with a note. Errors keep the ADR-17 style: the `AnimError` summary is the requester line, details go to stderr. The ILBM reader still refuses an ANIM handed to it directly, now with "This is an animation, not a picture".
  - **Rate**: files carry timing per frame in jiffies (1/60 s). The document rate is `60 * frames / total jiffies`, rounded to the nearest Set Rate value (1..60). Notes: "frame timing differs" when holds differ by more than one jiffy (one jiffy is rounding by a writer), "rounded" when the rate moved by more than 0.05, and a default of 30 for a file without timing. Per-frame CMAP changes cannot be kept (one palette per document): noted, the first palette is used.
  - **Save**: Anim ▸ Save.. (`anim.save`, "Save Animation") writes IFF ANIM (op 5, DPAN, loop frames) through `dpx_iff::anim::encode`. The suggested name is the picture's stem plus `.anim`; a picture or project extension becomes `.anim`, a name without extension gets `.anim` appended. Like Export it keeps the picture's name. Picture ▸ Export.. with a `.anim` name writes the same; Picture ▸ Save.. with a `.anim` name becomes `.dpxproj` as for other picture extensions. Rate: `holds_for_fps` spreads the rounding over the frames (25 per second = 2, 3, 2, 3 jiffies), so the total is exact; reading back averages, so rates that are not a whole number of jiffies per frame can come back one Set Rate step off with very few frames (25 per second with 3 frames reads as 26, with a "rounded" note). 30, 20, 15, 12, 10, ... are exact.
  - **A single-frame document exported as `.anim` gives a one-frame ANIM** (the codec writes a plain picture without closing frames). Chosen over a refusal because nothing is lost and the file opens as one frame.
  - **Stored/not stored**: CRNG, CAMG, pixel aspect, palette (first frame) and the rate are stored. Not stored, with a note: transparent colour, grab point, a screen size other than the picture's. Colours of ranges outside the palette are dropped with the existing note. The ILBM rules apply: `ilbm::write` refuses what an ILBM could not hold; nothing is reduced silently.
  - **CLI**: `info x.anim` prints format, size, colours, frame count, rate, CRNG lines, colours used over all frames and notes; `convert` reads and writes `.anim` (ANIM ↔ dpxproj keeps frames, palette, rate and ranges; ANIM → ILBM/PNG exports frame 1 with a note). `info` of a project now counts colours over all frames.
  - **MCP**: `open_picture` / `save_picture` accept `.anim` (`format: "iff_anim"`); ranges are not kept there (the MCP document model has no ranges), noted.
  - `menu::IMPLEMENTED` gets `anim.load` and `anim.save`. `--file-requester load-anim|save-anim` for snapshots.
- Deviations from DeluxePaint IV: Anim ▸ Load replaces the whole document (as Picture ▸ Load does), DeluxePaint loads into the frame sequence; the "# of Frames" field of the Load requester stays ghosted; what DeluxePaint IV itself writes is unverified (ADR-29).
- Verified (tests, run twice, green): app round trip through the requesters (3 frames, palette, rate, Load Animation / Save Animation titles, suggested name, Picture ▸ Load and Export with `.anim`, one-frame export), convert anim → dpxproj → anim with identical bytes, info text, timing/rounding notes, refused empty, cut and damaged ANIM files with short first lines, MCP round trip; CLI run by hand on a generated file.
- Not verified: any real ANIM file from DeluxePaint or an Amiga player (none available); the GUI by hand in the window.
