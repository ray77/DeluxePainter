# ADR-8: File requester and Picture ▸ Load/Save

- Status: accepted (Phase 2, 2026-11-10)
- Context: DeluxePaint IV AGA loads and saves pictures through its own file requester (manual figure 1.3 and the file requester reference, AGA p.209-212). DeluxePainter needs the same workflow, must write the document's display mode into ILBM files, and must never drop picture data silently.
- Decision:
  - **Own requester, not a native dialog.** `dpx_ui::file_requester::FileRequester` is drawn on the paint screen in LoRes UI pixels with the pens taken from the picture palette (like menus), centred on the UI screen (264×196, fits NTSC 320×200). It holds UI state only; the app lists drawers (`apps/deluxepainter/src/browse.rs`) and reads/writes files. Layout follows the manual figure: title, 8-row list with scroll arrows and a track with a dark knob, Drawer / Pattern / File fields (light text on dark bars, inverse block cursor), Disks / Assigns / Parent, "# of Frames" (Load only, ghosted until animation frames exist), Load or Save and Cancel. Geometry is measured from the scanned figure and still to calibrate.
  - **List:** sub-drawers, volumes and assigns first, shown as `<DIR>`, `<VOL>`, `<ASN>` plus the name in the `select` pen; then files, both sorted case-insensitively. Hidden entries (names starting with `.`) are not listed. A single click on a place lists it (the manual's tutorial opens a volume and then a drawer with single clicks); a click on a file puts its name into File; a double click (≤ 500 ms, same row) loads or saves. Mouse wheel and ↑/↓ scroll.
  - **Modern mapping of Amiga places:** Disks = mounted volumes (`/Volumes` on macOS; `/`, `/media/$USER`, `/run/media/$USER`, `/mnt` on Linux; drive letters on Windows). Assigns = well-known folders (Desktop, Documents, Downloads, Pictures, Home, Start = the start folder). The Drawer field takes full paths and `~`. Parent at the root does nothing. Only the macOS listing has been tried; Linux and Windows code paths are untested.
  - **Fields:** Return in Drawer lists it, Return in Pattern applies the pattern, Return in File (or with no field active) chooses Load/Save; Tab cycles the fields; Esc cancels. Patterns use AmigaDOS syntax (`?`, `#x`, `[a-z]`, `(a|b)`, `~`, `%`, `'`) via `dpx_ui::pattern`, case-insensitive; `*` is accepted as `#?` (DeluxePainter addition). A broken pattern lists all files and shows the reason. Names may be up to 255 characters (AmigaDOS allowed 30); the font draws only ASCII, other characters appear as `?`.
  - **Save format by name:** `.png` writes indexed PNG; `.jpg`/`.jpeg` (import-only), `.gif`, `.bmp`, `.tif(f)`, `.webp` and `.dpxproj` are refused with a message; every other name writes IFF ILBM, because Amiga names often carry no extension or tags like `.LoRes`. Replacing an existing file asks "… exists. Replace it?" with Yes / No (Y / N / Esc; Return does not confirm). Wording and box are ours. Files are written to a temporary file in the same drawer and renamed.
  - **What an ILBM save writes:** CAMG = the document target's mode id (AGA: full 32-bit id with PAL/NTSC monitor bits; OCS: the classic 16-bit view modes), BMHD x/y aspect from the display mode, page width/height = the mode's screen size, ByteRun1.
  - **Load:** the picture replaces the document; the display mode is guessed from CAMG and size (ADR-7). Load is not undoable and clears the undo history, like DeluxePaint's single-level undo cannot undo it either. Details the document model does not hold yet (CRNG colour ranges, GRAB, the transparent colour of masking 2) are kept in the app (`PictureExtras`) and written again on Save; ranges that fall outside a changed palette are left out with a note. A mask plane and private chunks (DPPS, DPPV, TINY …) are not kept: the notes say so (on stderr for now; a visible notice comes with the status/notification work).
  - The Pattern, Load and Save logic is covered by unit tests (`dpx-ui` requester tests, `files.rs`, `browse.rs`, and an app-level test that loads, replaces, saves PNG and refuses JPEG through the requester events).
- Consequences: Picture ▸ Save writes ILBM with the right mode for DeluxePaint and other Amiga readers; `.dpxproj` (lossless project) remains Phase 4. Brush/Palette/Anim Load/Save can reuse the requester with new `FileKind`s. A multi-frame "# of Frames" and frame-range boxes arrive with animation (Phase 6).
