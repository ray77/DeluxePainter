# ADR-31: Palette operations and the Effect menu

- Status: accepted (wave 4, 2026-11-10; decided while the owner was away, following `docs/research/manual-ui-notes.md` sections 2.5, 2.6, 3.4, 3.19)
- Context:
  - Color ▸ Palette ▸ Arrange, Color ▸ Remap, the Color Set items and most of Effect (AntiAlias, Process, Translucency, Stencil Show/Load/Save) were ghosted. The manual notes describe them only briefly, so a few details below are our reading, marked as such.
- Decision:
  - **Arrange** (`P`): a modal requester (`dpx-ui/arrange_requester.rs`) shows the palette as a grid of swatches. Dragging a swatch to another place moves it (the colours in between shift by one); the Ex button makes a drag exchange two swatches instead; Undo, Revert, Cancel, Ok. Ok runs one `Command::ArrangePalette { order }` (`order[new] = old`, a permutation, added at the end of the command enum): it reorders the palette and renumbers every pixel, so the picture looks identical; one undo step. The app then moves everything else that holds colour numbers: FG/BG, the stencil table (on and off), the custom and picked-up brushes, the fixed background and the spare page. Colour ranges (CRNG) stay where they are, because they are positions in the palette. DeluxePaint's Copy and Spread buttons are not part of it (they change colours, not their order; the Color Mixer's own buttons stay as they are).
  - **Remap**: the picture is repainted with the colours of the palette it was last in step with, looked up in the current palette (an identical colour wins, else the nearest; ties go to the lower index). The app remembers that palette when the palette changes by a single command (mixer, palette load, restore) and forgets it when the picture changes (a stroke, a load, another page) or after Remap or Arrange. One `SetPage` command, undoable (DeluxePaint cannot undo it). With nothing to remap, a note says so. Logic in `dpx_core::remap` (pure functions).
  - **Color Set ▸ Load.. / Save..** are the palette files: the document palette is the colour set here (at most 256 colours), there is no second set of 256 slots behind it, so no separate file format and no "Add / Overwrite" requester.
  - **Use Brush Palette** stays ghosted: `BrushImage` carries no palette, and brush loading fits the file's colours to the picture's palette (ADR-19), so no brush palette is kept.
  - **Effects are stored in the stroke and shape commands** as `fx: PaintFx` (`translucency`, `process`, `antialias`; left out of the JSON while off), so the GUI, CLI and MCP paint alike. `paint::plot_fx` applies them in the modes that set a colour (Matte, Color, Replace): the brush colour goes through Process against the page colour before the gesture, then is mixed with that page colour and snapped to the nearest palette colour. Reading the page before the gesture means painting over the same pixel twice in one stroke does not add up. `paint::plot` is `plot_fx` without effects, so nothing else changed.
  - **Translucency**: On/Off item, flag `T`, Settings.. requester with the share of the picture that stays (default 50 %, 0-100) as a number field instead of a slider. Weight of the paint = 100 - percent. Text is not translucent (manual). The manual's exceptions for 1-pixel airbrush and the 3 and 5 pixel built-in brushes are not reproduced.
  - **AntiAlias None / Low / High** (flags `a`, `A`): only for custom brushes, through `raster::Pen::stamp` (one added line: the brush pixel's cover from `paint::edge_cover`). Low mixes brush pixels that touch a transparent or outside pixel (4-neighbourhood) 50 % with the page; High weights every pixel by the share of opaque pixels in its 3x3 neighbourhood (isolated pixel 11 %, straight edge 66 %, inner 100 %). Cover multiplies with Translucency. Our own definition; the manual only says "smooth jaggies with intermediate shades".
  - **Process** (On/Off, Tint, Hue, Value; flag `P`): HSV based, f32 with basic arithmetic only. Tint takes hue and saturation from the brush colour and keeps the page's value, Hue only the hue, Value only the value. The manual says only "tint toward FG / substitute hue only / brightness only"; separating Tint from Hue by saturation is our reading. There is no "None" item in the menu.
  - **Stencil ▸ Show** (flag `s`, `S` otherwise): display only. The shown palette dims every unprotected colour to half and leaves protected ones as they are; the whole screen (UI too) uses it, like colour cycling. Painting on the page is off meanwhile; Show ends when the stencil is freed. Needs a stencil.
  - **Stencil ▸ Load.. / Save..**: our own tiny JSON text file `{"format":"dpx-stencil","version":1,"protected":[colour numbers]}`. The stencil is colour based, so DeluxePaint's area-based stencil layer file (screen-sized mask) cannot be represented. Load keeps colours inside the palette and says so when it drops others.
  - **Not done**: Background ▸ Lock FG (needs an area-based stencil, as do Stencil ▸ Paint and area stencil files) and Use Brush Palette stay ghosted; Color ▸ Recompute is HAM only and untouched.
  - Title bar: flags after the paint mode, `a`/`A` antialias, `B` fixed background, `P`, `S`/`s`, `T` (`UiState::flags`).
- Deviations from DeluxePaint IV: no Copy/Spread in Arrange; Remap undoable; Translucency value in a number field; stencil file format; Color Set = palette; Show dims the whole screen including the UI; Translucency/Process/AntiAlias settings are not stored in the project.
- Verified (unit and app tests, CI gate): permutation checks, move/exchange, Arrange keeps every pixel's colour and is one undo step, rejects bad orders, FG/BG/stencil/brushes/spare follow; Remap pixel-exact, one undo step, base forgotten after painting; translucency, cover, Process modes and AntiAlias values computed exactly; JSON round trip of `fx`; stencil file round trip through the file requester; Show disables painting; menu ids enabled/ghosted; headless snapshot `docs/design/screenshots/phase3-palette-ops.png` (translucent shapes and the Arrange requester).
- Not verified: by hand in the window; behaviour against the original program's exact pixel results; Process and AntiAlias formulas against DeluxePaint; large (HAM/EHB) screens.
- Review fix (2026-11-11): the undo step of `ArrangePalette` stores the inverse permutation instead of a document snapshot, so arranging an animation keeps no copies of its frames.
