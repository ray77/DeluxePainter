# ADR-28: Animation frames, playback and the Light Table

- Status: accepted (Phase 6 start, 2026-11-10; internal decisions taken without the owner, as CLAUDE.md allows; the project-format change below is the one item to show the owner)
- Context:
  - Phase 6 needs DeluxePaint-style animation: frames, Anim ▸ Frames / Control, the frame counter in the title bar, Effect ▸ LightTable, and frames saved in the project. ANIM import/export is a separate branch (the dpx-iff codec); AnimBrush and Move come later.
  - The rest of the app, the CLI and MCP only know one page (`Document::page()`), and every command must stay on the one command engine (ADR-2/6).
- Decision:
  - **Document**: 1..N frames of one size, one palette and one target; one page per frame (layers later). The current frame is "the page": `page()` returns it and every existing page command acts on it, so single-frame code is unchanged. The other frames sit behind `Arc`, so undo snapshots and frame copies share pixels (copy-on-write via `Arc::make_mut`). The document also holds the playback rate (default 30 fps).
  - **Limits**: at most 999 frames (DeluxePaint numbers a saved frame series with three digits) and at most 128 MiB of frame pixels (frames × width × height, one byte per pixel): 999 frames of 320×256, 130 of 1008×1024. `SetFrameCount`, `AddFrames`, `InsertFrameCopies`, `SetPageSize` and `SetFormat` are refused beyond that. The limit keeps a saved project inside the reader's 256 MiB / 1024-entry limits.
  - **Commands** (frame numbers from 0 in commands and MCP JSON, from 1 on screen): `SetFrameCount` (more = copies of the current frame inserted after it; fewer = delete from the current frame on, the last frames near the end — the manual's "step to frame 41, set 90" recipe), `AddFrames` (copies after the current frame, the last copy becomes current), `CopyFrame` (current frame onto a range; all frames = Copy to All), `InsertFrameCopies` (copies of a range inserted before a frame), `DeleteFrames` (the frame after the deleted range becomes current, the one before at the end; deleting every frame leaves one frame in the BG colour). Each is one undo step (whole-document snapshot, pixels shared). `SetPageSize` and `SetFormat` change every frame; `SetFormat` with "retain" checks the colours of all frames. `SetPage` with another page size is refused while there are several frames.
  - **Settings, not undo steps**: `GotoFrame` and `SetFrameRate` change the document (and its revision) but add no undo step and keep the redo list. Every undo step records the frame it ran on; undoing or redoing a pixel step of another frame first makes that frame current, so the change is visible. Undoing a frame command restores the frame that was current then; the rate is kept.
  - **Anim menu**: Frames ▸ Set #.., Add Frames.., Copy Frames.., Delete Frames..; Control ▸ Set Rate.., Previous (`1`), Next (`2`), Goto.. (`3`), Play (`4`), Play once (`5`), Ping-pong (`6`). Previous/Next wrap. Alt+`=` adds one frame. The requesters are small forms in the ADR-20 style (square corners, bitmap font, Return/Esc/Tab, Up/Down step numbers); a refused command keeps the requester open with the reason.
  - **Playback** only redraws: no command runs while playing; the shown frame is taken from the document by a pure timing function (`anim::play_position` / `anim::frame_at`). Play and Ping-pong start at the current frame, Play once at the first and stops on the last. Esc, Space or a mouse click stop; the frame on screen then becomes the current frame (one `GotoFrame`). Left/Right change the rate by one frame per second (a `SetFrameRate`). Playback is modal: nothing else reacts meanwhile.
  - **Title bar**: with more than one frame the left corner shows `current/count` (e.g. `2/3`) in place of the program name, followed by the paint mode ("the numbers 1/ 20 on the left side of the Title Bar", AGA p.84). One frame shows the program name as before.
  - **Light Table** (Effect ▸ LightTable; `l` On/Off, Alt+`l` Dim, Ctrl+`1`…`4` Two Back / Previous / Next / Spare, Merge): on screen only. Where the current frame has the BG colour, the first chosen image that is not BG there shows through, nearest first: Previous, Next, Two Back, then the spare page. Neighbours wrap around like Previous/Next. **Dim** (on by default) maps each colour to the palette entry nearest to the halfway mix of that colour and the BG colour, never to BG itself — the only dimming an indexed palette allows; the document never changes. Previous starts on, the others off (the manual does not say). **Merge** copies the visible images (not dimmed) into the current frame as one `SetPage` and switches the Light Table off.
  - **Project format** (owner-visible): single-frame documents are still written as `format_version` 1, byte for byte as before (checked against a file written by the old writer, `crates/dpx-formats/tests/data/v1-single-frame.dpxproj`), so older builds keep reading them. Documents with several frames are written as **`format_version` 2**: the `frames` array lists every frame (`frames/<n>/layers/0.png`), plus `current_frame` (from 0) and `fps`. This build reads versions 1 and 2; older builds refuse version 2 by name instead of losing frames. See `docs/PROJECT_FORMAT.md`.
  - **Export**: Picture ▸ Export.., `convert` and MCP `save_picture` of an animation write the current frame as ILBM/PNG and say so in a note ("frame 2 of 3 exported as a picture"); IFF ANIM export arrives with the codec branch.
  - The spare page keeps every frame when it takes over the shown page's palette (`Document::with_palette`), so swapping an animation to the spare and back loses nothing.
- Deviations from DeluxePaint IV:
  - Copy Frames and Delete Frames choose with radio buttons and Ok; DeluxePaint acts through a button beside each choice (Range, All Frames).
  - Frame commands, Light Table Merge, Copy Frames and Delete Frames are undoable (DeluxePaint: one undo level, Merge not undoable); undo/redo step back to the frame they belong to.
  - The frame counter replaces the program name (our reading of AGA p.84; the exact look of the original was not checked on a capture).
  - Not yet: Set Range (play range), the Animation Control Panel (Alt-a), Method, Move, AnimBrush, animpainting (Alt while painting), Load/Save Anim, Shift-1/2/3/4/5 (first/last/last go-to/reverse play), `r` reverse while playing, the Clear requester for several frames (CLR clears the current frame), and check marks on the LightTable items (they need a shared check-mark mechanism in `menu.rs`). Picture ▸ Load replaces the whole document, not only the current frame.
  - The Light Table shows at most Previous, Next, Two Back and Spare (DeluxePaint: "max four images") with our nearest-first order.
- Verified (all by automated tests and headless snapshots in this worktree, macOS):
  - dpx-core: frame commands with current-frame rules, limits, undo across frames, page commands on the current frame, SetPageSize/SetFormat on every frame, GotoFrame/SetFrameRate without undo steps, JSON names; Light Table composition, dim table, playback timing.
  - dpx-formats: 3-frame round trip as version 2 (frames, current frame, rate, spare, deterministic bytes), version-2 rules, single-frame byte identity with the version-1 fixture, version 3 named.
  - App: Set #.. / Add / Copy / Delete / Goto / Set Rate requesters through the engine, keys `1` `2` `l` Alt+`l` Ctrl+`3`, undo going back to its frame, playback timing and stop frame, Light Table display and undoable Merge, project save/load/info and ILBM export note, small pages growing in every frame.
  - Snapshot `docs/design/screenshots/phase6-anim.png` (frame 2 of 3 with Previous and Next dimmed) and `phase6-anim-copy-frames.png`, looked at.
- Not verified: real key and mouse input in the window (Alt+`l` and Ctrl+digits on macOS keyboards in particular), playback smoothness in the running app, Windows/Linux, opening a version-2 project in an older build (expected: "Project is from a newer version").

Note: a single-frame document with a non-default fps is written as format version 2 (v1 has no fps); the reader refuses a target screen its mode does not allow.
