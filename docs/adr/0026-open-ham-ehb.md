# ADR-26: Opening EHB and HAM pictures (interim)

- Status: accepted (interim until layers; ADR-4's RGBA layer + raw planes come in Phase 4/5)
- Context: ADR-25 added the codecs, but the ILBM reader still refused HAM/EHB (ADR-17: "arrive in Phase 5"). Real Amiga pictures use these modes, so Picture ▸ Load, `info` and `convert` should open them now, without waiting for layers.
- Decisions:
  - **Reader (`dpx-iff`):** no longer refuses EHB/HAM. `Ilbm::special: Option<SpecialMode>` (`Ehb`, `Ham6`, `Ham8`) says what the file is; `Ilbm::image` holds the raw per-pixel plane value and `palette` only the entries the mode reads (EHB 32, HAM6 16, HAM8 64; extra CMAP entries are dropped with a note, e.g. "CMAP has 64 colours but EHB reads 32"). Mode detection: CAMG HAM bit with 6 planes = HAM6, 8 planes = HAM8, other plane counts refused (`HAM with 5 bitplanes`); CAMG EHB bit with 6 planes = EHB, with other counts ignored with a note; plain CAMG on 6 planes = a normal 64-colour picture. **Without CAMG, 6 planes** follow IFF_SUPPORT_MATRIX: a CMAP with exactly 32 entries = EHB, anything else = HAM6 (the spec's guess), each with a note. 8 planes without CAMG stay plain 256 colours. DEEP, 24/32 planes, >8 planes stay refused. The writer refuses `special` pictures and CAMG values with the HAM/EHB bit, so nothing is silently reinterpreted.
  - **EHB (app, `files::load`):** opens as a plain indexed 64-colour picture: palette = `ehb_palette(base 32)` (entries 32-63 are base >> 1; with 4-bit precision when every base colour is a 12-bit value or the CMAP had the 0xN0 form, else 8-bit), pixels exact, the EHB bit removed from CAMG (a missing CAMG becomes a plain one, otherwise a 6-plane file without CAMG would read as HAM again). The target is the default AGA screen, which holds 64 colours. A note says the picture is edited as 64 free colours until EHB editing exists and that saving writes a 64-colour 6-plane ILBM, not EHB. Save and ILBM -> ILBM `convert` validate as for any 64-colour picture; nothing is reduced.
  - **HAM6/HAM8 (app):** decoded with `decode_ham` to RGB and handed on as `Picture::TrueColor` with format `HAM6`/`HAM8`, then reduced exactly like a true-colour PNG (ADR-9: size/mode guessed from the picture size, palette of the mode's size, Floyd-Steinberg). The CAMG (interlace/HiRes) is not used for the mode guess, only the size (320 wide = LoRes, 640 = HiRes). Notes: "HAM6 picture reduced to N colours (Floyd-Steinberg dithering); HAM export comes later", or, when the picture has few enough colours, "HAM6 picture opened as an indexed picture with its N colours; HAM export comes later". `info` prints `IFF ILBM HAM6 (decoded to RGB)` plus the load notes.
  - Fixtures: `ham6-16x2.iff` (the old `broken-ham.iff`, which was a valid HAM6 file), `ham8-16x2.iff`, `ehb-16x2.iff`, all self-made by the builders in `crates/dpx-iff/tests/golden.rs`. The refusal tests for HAM/EHB/"six planes without CAMG" became reading tests; the refused list shrank from 22 to 19.
- Verified: unit and fixture tests (raw plane values and notes, EHB exact indices and 64 colours, EHB save/convert round trip as 6-plane non-EHB ILBM, HAM6/HAM8 decoded pixels hand-computed, reduction note on a 64x64 HAM6, `info` text). The local `Examplepics/` folder holds no EHB or HAM file (all 5 or 8 planes).
- Not verified: any real-world EHB/HAM file (ADR-25's open points stand: HAM8 control-bit location, line start colour, control-code mapping); the 6-planes-without-CAMG guess (a plain 64-colour file without CAMG would be read as HAM6); EHB with 64-entry CMAPs (entries 32-63 are ignored even if a writer stored non-derived values); 8-bit vs 4-bit half-brite choice for AGA files whose colours happen to be 12-bit values.
- Consequences: a HAM picture is lossy on load (reduced to the screen's palette) and its saved copy is plain indexed. Phase 4/5 replace this with the RGBA layer plus raw planes (ADR-4), where the same reader output feeds the layer and the original planes stay the source of truth.

Note: a plain 6-plane ILBM is always written with a CAMG chunk (0), so it can never read back as HAM6; HAM load notes every dropped CRNG/GRAB/mask/extra chunk.
- Review fix (fix/mcp): MCP `open_picture` follows this ADR for EHB (64 free colours, EHB bit cleared) and refuses HAM with UNSUPPORTED_FILE_TYPE.
